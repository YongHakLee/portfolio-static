# 기초개념 2 — 딥러닝 · CNN

---

## 이 문서를 읽는 법

논문 13편 중 9편이 신경망을 쓴다. 이 문서는 그 9편을 읽기 위한 공통 언어다.

통계 전공자가 딥러닝 질문을 받을 때 흔한 함정이 두 가지 있다. 하나는 **모델 이름만 나열하는 것**이다. "YOLO를 썼고 HRNet을 썼습니다"는 답이 아니다. 왜 그 구조가 그 문제에 맞는지 말할 수 있어야 한다. 다른 하나는 **최신 모델을 모른다고 위축되는 것**이다. 면접관이 실제로 확인하려는 건 최신 논문 목록이 아니라, 신경망이 왜 학습되는지와 언제 실패하는지를 아는가다.

그래서 이 문서는 구조의 나열보다 **왜 그 구성요소가 생겼는가**에 무게를 뒀다. 배치 정규화는 어떤 문제를 풀려고 나왔는지, 잔차 연결이 없으면 무엇이 안 되는지 같은 것이다. 이런 식으로 이해해 두면 처음 보는 구조도 "아, 이건 이 문제를 이렇게 푼 거구나"로 읽힌다.

순서는 **신경망의 학습 원리(퍼셉트론~옵티마이저) → 학습을 되게 만드는 장치(BN·드롭아웃) → CNN의 구조(합성곱~백본) → 실전(전이학습·경량화)** 이다. 트랜스포머는 마지막에 개요만 두었다. T02 논문이 LLM을 쓰기 때문에 최소한의 언어는 필요하지만, 상세한 것은 [06_강화학습·시계열·기타.md](06_강화학습·시계열·기타.md)의 LLM 절에 있다.

## 개념 목록

### 퍼셉트론과 다층 신경망

**직관**

퍼셉트론 하나는 로지스틱 회귀와 거의 같다. 입력에 가중치를 곱해 더하고, 그 결과를 비선형 함수에 통과시킨다. 이걸 하나만 쓰면 직선(초평면)으로만 데이터를 가를 수 있어서, XOR처럼 직선으로 못 가르는 문제를 못 푼다.

층을 쌓으면 달라진다. 앞 층이 만든 표현을 뒤 층이 다시 조합하기 때문에, 층이 깊어질수록 더 복잡한 경계를 그릴 수 있다. **핵심은 층 사이에 비선형 함수가 있어야 한다**는 것이다. 없으면 아무리 층을 쌓아도 선형 변환의 합성이라 결국 하나의 선형 변환과 같아진다.

**정의**

- 퍼셉트론: 입력의 가중합에 활성함수를 적용해 출력을 내는 단위
- 다층 퍼셉트론(MLP): 퍼셉트론 층을 여러 개 쌓고 모든 노드가 다음 층과 연결된(완전연결) 신경망
- 보편 근사 정리: 은닉층이 하나뿐이어도 노드가 충분하면 임의의 연속함수를 원하는 정확도로 근사할 수 있다

**핵심 수식**

한 층의 연산:

```
h = σ(Wx + b)
```

- `x`: 입력 벡터
- `W`: 가중치 행렬
- `b`: 편향 벡터
- `σ`: 활성함수
- `h`: 이 층의 출력(은닉 표현)

**면접 포인트**

보편 근사 정리는 "가능하다"는 존재 정리일 뿐, **얼마나 많은 노드가 필요한지도, 학습으로 찾을 수 있는지도 말해 주지 않는다.** 실제로는 넓고 얕은 망보다 좁고 깊은 망이 같은 함수를 훨씬 적은 파라미터로 표현한다. "은닉층 하나면 다 된다면서 왜 깊게 쌓나요"라는 질문의 답이 이것이다.

P2(가스배관)에서 MLP를 쓰다 실패한 원인이 **입력 크기 고정 제약**이었는데, 이는 완전연결층이 입력 차원을 미리 정해 두는 구조에서 나온다. 가변 길이 신호를 다루려면 잘라내거나 채워 넣어야 하고, 그 과정에서 정보가 왜곡된다.

### 활성함수

**직관**

층 사이에 넣는 비선형 함수다. 없으면 깊은 망이 의미가 없다. 어떤 함수를 쓰느냐가 학습 속도와 안정성을 좌우한다.

**정의와 비교**

| 함수 | 식 | 출력 범위 | 문제점 |
|------|-----|-----------|--------|
| 시그모이드 | 1/(1+e^(−x)) | (0, 1) | 양끝에서 기울기가 0에 수렴 → 기울기 소실. 출력이 0 중심이 아님 |
| tanh | (e^x−e^(−x))/(e^x+e^(−x)) | (−1, 1) | 0 중심이지만 여전히 기울기 소실 |
| ReLU | max(0, x) | [0, ∞) | 음수 입력에서 기울기가 0 → 죽은 뉴런 |
| Leaky ReLU | max(αx, x), α≈0.01 | (−∞, ∞) | 죽은 뉴런 완화 |
| GELU | x·Φ(x) | (−∞, ∞) | 트랜스포머에서 표준적으로 쓰임 |
| Swish/SiLU | x·σ(x) | (−∞, ∞) | EfficientNet, MobileNetV3에서 사용 |

**면접 포인트**

**기울기 소실(vanishing gradient)** 이 왜 생기는지가 핵심이다. 역전파는 각 층의 기울기를 곱해 가며 앞쪽으로 전달하는데, 시그모이드의 미분값은 최대 0.25다. 층을 10개 지나면 0.25의 10제곱, 즉 백만 분의 1 수준으로 줄어 앞쪽 층이 사실상 학습되지 않는다.

ReLU가 이를 크게 완화했다. 양수 구간의 미분이 정확히 1이라 곱해도 줄지 않기 때문이다. 대신 음수 구간에서 기울기가 0이라 한번 죽은 뉴런은 되살아나지 않는데, 이것이 Leaky ReLU가 나온 이유다.

MobileNetV3에서 h-swish를 쓰는 이유는 성능과 연산량의 절충이다. Swish가 성능이 좋지만 시그모이드 계산이 모바일에서 비싸서, 이를 구간 선형 함수로 근사한 것이 h-swish다. 온디바이스 추론을 다룬 경험이 있다면 이 지점을 짚을 수 있어야 한다.

### 역전파

**직관**

출력에서 발생한 오차를 뒤에서 앞으로 되돌리며, 각 가중치가 그 오차에 얼마나 기여했는지 계산하는 절차다. 원리는 미적분의 **연쇄법칙**이 전부다. "이 가중치를 조금 바꾸면 손실이 얼마나 변하나"를 층별로 이어 붙여 계산한다.

효율의 비밀은 **중간 결과를 재사용한다**는 데 있다. 각 가중치마다 처음부터 미분을 다시 계산하면 감당이 안 되는데, 뒤 층에서 계산한 기울기를 앞 층이 그대로 받아 쓰기 때문에 전체 비용이 순전파와 같은 수준으로 유지된다.

**정의**

순전파로 예측과 손실을 계산하고, 연쇄법칙을 이용해 손실에 대한 각 파라미터의 편미분을 출력층부터 입력층 방향으로 계산하는 알고리즘이다.

**핵심 수식**

연쇄법칙:

```
∂L/∂W⁽ˡ⁾ = (∂L/∂h⁽ˡ⁾) · (∂h⁽ˡ⁾/∂W⁽ˡ⁾)
```

- `L`: 손실
- `h⁽ˡ⁾`: l번째 층의 출력
- `W⁽ˡ⁾`: l번째 층의 가중치

앞쪽 층으로 전달되는 기울기는 뒤쪽 층들의 기울기가 **곱해진** 형태가 된다. 이 곱이 1보다 작으면 기울기 소실, 크면 기울기 폭발이 일어난다.

**면접 포인트**

"기울기 소실과 폭발을 어떻게 막나"에 대한 대응책 목록을 준비한다: 활성함수 교체(ReLU 계열), 가중치 초기화(He·Xavier), 배치 정규화, 잔차 연결, 기울기 클리핑(폭발 쪽). 이 다섯 개가 나오면 충분하다.

### 경사하강법과 옵티마이저

**직관**

손실이 줄어드는 방향으로 파라미터를 옮기는데, **얼마나 크게, 어떤 방향으로** 옮길지가 옵티마이저의 차이다. 단순 경사하강법은 매번 현재 기울기만 본다. 모멘텀은 이전에 가던 방향의 관성을 더해 골짜기에서 지그재그로 튀는 걸 줄인다. Adam은 여기에 더해 파라미터마다 학습률을 다르게 조절한다.

**정의와 비교**

| 옵티마이저 | 아이디어 | 특징 |
|------------|----------|------|
| SGD | 미니배치 기울기로 갱신 | 단순. 잘 튜닝하면 일반화가 좋다 |
| SGD + Momentum | 이전 갱신 방향을 누적 | 진동 감소, 수렴 가속 |
| RMSProp | 기울기 제곱의 이동평균으로 학습률 조정 | 파라미터별 적응 |
| Adam | 모멘텀 + RMSProp | 기본값으로도 잘 돌아감. 가장 널리 쓰임 |
| AdamW | Adam의 weight decay를 분리 | 정규화가 제대로 작동. 트랜스포머 표준 |

**핵심 수식**

미니배치 경사하강법:

```
θ ← θ - η · (1/B) Σᵢ ∇θ L(xᵢ, yᵢ)
```

- `η`: 학습률
- `B`: 미니배치 크기

Adam의 갱신:

```
mₜ = β₁mₜ₋₁ + (1-β₁)gₜ          (기울기의 1차 모멘트, 방향)
vₜ = β₂vₜ₋₁ + (1-β₂)gₜ²         (기울기의 2차 모멘트, 크기)
θ ← θ - η · m̂ₜ / (√v̂ₜ + ε)
```

- `gₜ`: 현재 기울기
- `β₁, β₂`: 감쇠율. 보통 0.9, 0.999
- `m̂ₜ, v̂ₜ`: 초기 편향을 보정한 값
- `ε`: 0으로 나누는 것을 막는 작은 수

**면접 포인트**

"Adam이 항상 좋은가"라는 질문에 그렇다고 답하면 안 된다. 이미지 분류에서는 잘 튜닝된 SGD+Momentum이 Adam보다 **일반화 성능이 더 좋게** 나오는 경우가 흔하다. Adam은 빠르게 수렴하지만 더 평평하지 않은 최소점으로 가는 경향이 보고돼 있다. 실무 답변으로는 "Adam으로 빠르게 기준선을 잡고, 최종 성능이 필요하면 SGD+Momentum과 학습률 스케줄로 다시 학습한다"가 자연스럽다.

배치 크기와 학습률의 관계도 자주 묻는다. 배치를 키우면 기울기 추정이 안정돼 학습률을 함께 키울 수 있다(선형 스케일링 규칙). 배치만 키우고 학습률을 그대로 두면 학습이 느려진다.

### 배치 정규화

**직관**

층을 지날수록 데이터의 분포가 계속 바뀐다. 앞 층의 가중치가 갱신되면 뒤 층이 받는 입력의 분포도 따라 변하고, 뒤 층은 매번 새 분포에 적응하느라 학습이 느려진다. 배치 정규화는 각 층의 입력을 미니배치 단위로 평균 0, 분산 1로 맞춰 이 변동을 줄인다.

**정의**

미니배치 내에서 각 채널(또는 특징)별로 정규화한 뒤, 학습 가능한 스케일 γ와 시프트 β로 다시 조정하는 층이다.

**핵심 수식**

```
x̂ = (x - μ_B) / √(σ²_B + ε)
y = γ x̂ + β
```

- `μ_B, σ²_B`: 미니배치의 평균과 분산
- `ε`: 분모가 0이 되지 않게 하는 작은 수
- `γ, β`: 학습되는 파라미터. 정규화가 표현력을 해치지 않도록 원래 분포로 되돌릴 여지를 남긴다

**추론 시**

미니배치가 없으므로, 학습 중에 누적한 이동평균·이동분산을 쓴다. 이 때문에 학습 모드와 추론 모드를 반드시 구분해야 한다(PyTorch의 `model.train()` / `model.eval()`).

**정규화 기법 비교**

| 기법 | 정규화 단위 | 배치 크기 의존 | 주 용도 |
|------|-------------|----------------|---------|
| Batch Norm | 배치 × 공간 (채널별) | 있음 | CNN |
| Layer Norm | 한 샘플의 전 특징 | 없음 | 트랜스포머, RNN |
| Instance Norm | 한 샘플의 한 채널 | 없음 | 스타일 변환, 생성모델 |
| Group Norm | 채널을 그룹으로 묶어 | 없음 | 배치가 작을 때 |

**면접 포인트**

세 가지가 자주 나온다.

첫째, **추론 시 어떻게 하는가.** 이동평균을 쓴다고 답해야 한다.

둘째, **배치가 작으면 왜 문제인가.** 배치 통계량의 추정이 불안정해진다. 배치가 2~4라면 Group Norm이나 Layer Norm으로 바꾼다. 고해상도 분할이나 검출 과제에서 메모리 때문에 배치를 작게 잡을 수밖에 없을 때 실제로 겪는 문제다.

셋째, **왜 효과가 있는가.** 원 논문은 내부 공변량 변화(internal covariate shift) 감소로 설명했지만, 이후 연구에서 손실 지형을 매끄럽게 만들어 더 큰 학습률을 쓸 수 있게 하는 효과가 더 크다는 분석이 나왔다. 이 논쟁을 알고 있으면 깊이가 드러난다.

### 드롭아웃과 데이터 증강

**직관**

드롭아웃은 학습할 때마다 뉴런 일부를 무작위로 꺼 버린다. 특정 뉴런에 과하게 의존하지 못하게 만들어, 여러 개의 작은 망을 앙상블하는 효과를 낸다.

데이터 증강은 데이터를 늘리는 대신 **같은 데이터를 여러 모습으로 보여 주는** 방법이다. 고양이를 좌우로 뒤집어도 고양이라는 사실을 모델에게 알려 주는 것이다.

**정의**

- 드롭아웃: 학습 시 각 뉴런을 확률 p로 0으로 만들고, 남은 값을 1/(1−p)로 나눠 기댓값을 맞춘다. 추론 시에는 전부 켠다.
- 데이터 증강: 레이블이 바뀌지 않는 범위에서 입력에 변형을 가한다.

**증강 기법**

| 유형 | 예 | 주의점 |
|------|-----|--------|
| 기하 변환 | 회전, 이동, 좌우 반전, 크롭, 스케일 | 상하 반전은 문자·인체에서 부적절 |
| 색상 변환 | 밝기, 대비, 채도, 색조 | 색이 레이블인 과제에서는 금지 |
| 잡음 | 가우시안 잡음, 블러 | 실제 센서 잡음과 유사한지 확인 |
| 혼합 | Mixup, CutMix | 분류에 효과적. 검출·분할에는 조정 필요 |
| 소거 | Random Erasing, Cutout | 가림에 대한 강건성 |

**면접 포인트**

**"증강이 실제 변동을 반영하는가"** 가 핵심 판단 기준이다. 3D 계측 과제에서 이미지를 무작위로 스케일 변환하면, 실제 물리적 크기 정보가 깨져 측정 과제 자체가 무의미해진다. 증강은 과제의 불변성(invariance)을 정확히 이해한 뒤에 골라야 한다.

드롭아웃과 배치 정규화를 함께 쓰면 성능이 떨어지는 경우가 보고돼 있다. 드롭아웃이 분산을 바꿔 BN의 통계량 추정과 충돌하기 때문이다. 최근 CNN은 BN을 쓰고 드롭아웃은 마지막 완전연결층에만 쓰거나 생략하는 경우가 많다.

### 합성곱 연산

**직관**

완전연결층은 이미지의 모든 픽셀을 모든 뉴런에 연결한다. 224×224 이미지 하나에 대해 첫 층만 수천만 개 가중치가 필요하고, 고양이가 왼쪽에 있을 때와 오른쪽에 있을 때를 따로 배워야 한다.

합성곱은 작은 필터(예: 3×3)를 이미지 전체에 미끄러뜨리며 같은 가중치를 재사용한다. 파라미터가 급감하고, **위치가 달라도 같은 패턴을 인식한다**(평행이동 등변성). 앞쪽 층은 모서리와 색 변화 같은 단순한 패턴을, 뒤로 갈수록 눈·바퀴 같은 복합적인 패턴을 잡는다.

**정의**

입력의 국소 영역과 커널(필터)의 가중합을 계산해 특징 맵을 만드는 연산이다. 국소 연결성과 가중치 공유가 두 가지 핵심 성질이다.

**핵심 수식**

출력 크기:

```
O = ⌊(I + 2P - K) / S⌋ + 1
```

- `I`: 입력 크기
- `K`: 커널 크기
- `P`: 패딩
- `S`: 스트라이드
- `O`: 출력 크기

파라미터 수(편향 제외):

```
파라미터 = K × K × C_in × C_out
```

- `C_in, C_out`: 입력·출력 채널 수

**합성곱의 변형**

| 종류 | 설명 | 쓰이는 곳 |
|------|------|-----------|
| 표준 합성곱 | 위 수식 그대로 | 일반 CNN |
| 1×1 합성곱 | 공간은 안 보고 채널만 섞음 | 채널 수 조정, 병목 구조 |
| 깊이별 분리 합성곱 | 채널별 공간 합성곱 + 1×1로 채널 결합 | MobileNet, EfficientNet |
| 확장 합성곱(dilated) | 커널 사이에 간격을 둠 | 해상도 유지하며 수용영역 확대. DeepLab |
| 전치 합성곱 | 해상도를 키움 | 디코더, 생성모델 |

**면접 포인트**

**깊이별 분리 합성곱의 연산량 절감 비율**을 계산할 수 있으면 좋다. 표준 합성곱이 `K²·C_in·C_out`인 반면, 깊이별 분리는 `K²·C_in + C_in·C_out`이다. 비율은 대략 `1/C_out + 1/K²`이고, K=3에 C_out이 크면 약 1/9 수준으로 줄어든다. 이것이 MobileNet이 모바일에서 도는 이유이고, P1·P3의 온디바이스 제약과 직결된다.

### 풀링과 수용영역

**직관**

풀링은 특징 맵을 줄이는 연산이다. 2×2 영역에서 최댓값만 남기면 크기가 절반이 되고, 위치가 조금 흔들려도 같은 값이 나와 작은 이동에 둔감해진다.

수용영역(receptive field)은 **출력의 한 픽셀이 원본 이미지의 얼마나 넓은 영역을 보고 있는가**다. 3×3 합성곱을 두 번 쌓으면 5×5 영역을, 세 번 쌓으면 7×7 영역을 본다. 층이 깊어질수록 넓은 맥락을 본다는 뜻이다.

**정의**

- 최대 풀링(Max Pooling): 영역 내 최댓값. 두드러진 특징을 남긴다
- 평균 풀링(Average Pooling): 영역 내 평균
- 전역 평균 풀링(GAP): 각 채널을 하나의 값으로 압축. 완전연결층을 대체해 파라미터를 크게 줄인다

**핵심 수식**

수용영역의 누적:

```
RF_l = RF_(l-1) + (K_l - 1) × Π_(i<l) S_i
```

- `RF_l`: l번째 층의 수용영역 크기
- `K_l`: l번째 층의 커널 크기
- `S_i`: i번째 층까지의 스트라이드 누적곱

**면접 포인트**

수용영역은 **과제에 맞게 설계해야 하는 값**이다. 작은 결함을 찾는 과제에서 수용영역이 지나치게 크면 배경에 묻히고, 전체 형상을 봐야 하는 과제에서 너무 작으면 맥락을 놓친다.

분할 과제에서 풀링이 딜레마를 만든다. 넓은 맥락을 보려면 다운샘플링해야 하는데, 그러면 픽셀 단위 정확도가 떨어진다. 이 딜레마를 푼 방법이 U-Net의 스킵 연결, DeepLab의 확장 합성곱, HRNet의 고해상도 유지다. 세 가지가 같은 문제의 서로 다른 해법이라는 점을 알면 [03_비전_검출·분할·키포인트.md](03_비전_검출·분할·키포인트.md)가 훨씬 쉽게 읽힌다.

### CNN 백본의 계보 (VGG → ResNet → EfficientNet)

**직관**

CNN의 역사는 "어떻게 하면 더 깊게 쌓아도 학습이 되는가"와 "어떻게 하면 같은 성능을 더 적은 연산으로 내는가"의 두 축으로 흘러왔다.

**계보**

| 모델 | 연도 | 핵심 아이디어 | 남긴 것 |
|------|------|---------------|---------|
| LeNet-5 | 1998 | 합성곱+풀링의 원형 | CNN의 기본 구조 |
| AlexNet | 2012 | ReLU, 드롭아웃, GPU 학습 | 딥러닝 부흥의 출발점 |
| VGG | 2014 | 3×3 합성곱만 깊게 쌓음 | 단순한 설계 원칙. 지금도 특징 추출기로 쓰임 |
| GoogLeNet/Inception | 2014 | 여러 크기 필터를 병렬로, 1×1로 차원 축소 | 연산 효율 개념 도입 |
| ResNet | 2015 | 잔차 연결 | 100층 이상 학습 가능. 현대 CNN의 표준 |
| DenseNet | 2016 | 모든 앞 층을 뒤 층에 연결 | 특징 재사용 |
| MobileNet | 2017~ | 깊이별 분리 합성곱 | 모바일 추론 |
| EfficientNet | 2019 | 깊이·너비·해상도를 함께 스케일링 | 복합 스케일링 |
| ConvNeXt | 2022 | 트랜스포머 설계를 CNN에 역수입 | CNN이 여전히 경쟁력 있음을 보임 |

**면접 포인트**

"VGG는 왜 3×3만 쓰나"가 좋은 질문이다. 3×3을 두 번 쌓으면 5×5와 수용영역이 같은데 파라미터는 `2×9=18`로 `25`보다 적고, 사이에 비선형이 한 번 더 들어가 표현력이 늘어난다. 작은 필터를 깊게 쌓는 것이 유리하다는 원칙이 여기서 정립됐다.

백본을 고르는 실무 기준도 준비한다. 정확도만 필요하면 ResNet 계열, 모바일·엣지면 MobileNet 계열, 정확도와 연산량의 균형이면 EfficientNet이다. P1·P3처럼 모바일 제약이 있는 과제에서 MobileNetV3를 고른 판단이 여기에 근거한다.

### 잔차 연결

**직관**

층을 깊게 쌓았더니 오히려 성능이 나빠지는 현상이 있었다. 과적합이면 학습 성능은 좋아야 하는데 **학습 성능조차 나빠졌다.** 최적화 자체가 안 되는 문제였다.

잔차 연결은 층의 출력에 입력을 그대로 더한다. 이러면 그 층이 "아무것도 안 하기"를 배우는 게 쉬워진다. 가중치를 0으로 만들면 입력이 그대로 통과하기 때문이다. 깊게 쌓아도 최소한 얕은 망만큼은 하도록 보장된다.

**정의**

블록의 출력에 입력을 항등 사상으로 더하는 구조다. 학습해야 할 대상이 목표 함수 H(x) 자체가 아니라 잔차 F(x) = H(x) − x가 된다.

**핵심 수식**

```
y = F(x, {Wᵢ}) + x
```

- `F`: 학습되는 잔차 함수(합성곱 층들)
- `x`: 입력. 이 항이 지름길(shortcut)이다

역전파 시 기울기가 `∂y/∂x = ∂F/∂x + 1`이 되어, `+1` 덕분에 기울기가 곱셈으로 소멸하지 않고 앞 층까지 전달된다.

**면접 포인트**

**"기울기가 곱해지는 경로 옆에 더해지는 경로를 하나 만든 것"** 이라는 설명이 핵심이다. 이 한 줄이 잔차 연결의 본질이고, 트랜스포머·U-Net·DenseNet이 모두 같은 아이디어를 쓴다.

입력과 출력의 채널 수나 해상도가 다르면 그냥 더할 수 없어서 1×1 합성곱으로 맞춰 준다(projection shortcut). 세부 구현을 묻는 후속 질문에 대비해 둔다.

### MobileNet 계열과 경량화

**직관**

모바일 기기에서 실시간으로 돌리려면 연산량과 메모리를 줄여야 한다. MobileNet은 표준 합성곱을 **공간 방향 처리와 채널 방향 처리로 분리**해 연산량을 한 자릿수 줄였다.

**계보**

| 버전 | 핵심 |
|------|------|
| MobileNetV1 | 깊이별 분리 합성곱 도입 |
| MobileNetV2 | 역병목 구조(inverted residual) + 선형 병목. 채널을 늘렸다 줄이는 순서로 잔차를 적용 |
| MobileNetV3 | 신경망 구조 탐색(NAS)으로 구조 최적화 + SE 블록 + h-swish |

**핵심 수식**

표준 합성곱 대비 깊이별 분리 합성곱의 연산량 비율:

```
비율 = 1/C_out + 1/K²
```

- `C_out`: 출력 채널 수
- `K`: 커널 크기

K=3, C_out=256이면 약 0.115로, 연산량이 대략 1/9 수준이 된다.

**경량화 기법 전반**

| 기법 | 설명 | 대가 |
|------|------|------|
| 구조 설계 | 깊이별 분리 합성곱, 채널 축소 | 설계 비용 |
| 양자화 | 32비트 부동소수를 8비트 정수로 | 약간의 정확도 손실 |
| 가지치기(pruning) | 중요도가 낮은 가중치·채널 제거 | 재학습 필요 |
| 지식 증류 | 큰 모델의 출력을 작은 모델이 흉내 | 교사 모델 학습 비용 |
| 입력 해상도 축소 | 이미지를 작게 | 작은 대상 탐지 성능 하락 |

**면접 포인트**

"모바일에서 실시간으로 돌렸다"는 말을 하면 **어떤 기준으로 실시간인지, 어떤 기기에서 몇 ms인지**가 반드시 따라온다. 각 논문의 6절(실험 세팅)에서 이 수치를 확인해 두어야 한다.

경량화를 물었을 때 양자화만 말하지 말고 **구조 설계 → 입력 해상도 → 양자화 → 가지치기** 순으로 검토했다고 답하는 편이 좋다. 가장 큰 효과는 대개 구조와 해상도에서 나오기 때문이다.

---

### 전이학습과 파인튜닝

**직관**

수백만 장으로 학습된 모델은 이미 모서리·질감·형태 같은 일반적인 시각 특징을 안다. 내 과제의 데이터가 적을 때, 이 지식을 가져와 마지막 부분만 새로 배우게 하면 훨씬 적은 데이터로 쓸 만한 성능이 나온다.

**정의와 전략**

| 전략 | 방법 | 적합한 상황 |
|------|------|-------------|
| 특징 추출 | 백본을 얼리고 분류기만 학습 | 데이터가 아주 적고, 도메인이 사전학습과 비슷할 때 |
| 부분 파인튜닝 | 뒤쪽 층 일부만 학습 | 데이터가 중간 규모 |
| 전체 파인튜닝 | 전 층을 낮은 학습률로 학습 | 데이터가 충분하거나 도메인 차이가 클 때 |
| 층별 학습률 | 앞 층은 낮게, 뒤 층은 높게 | 도메인 차이가 있으면서 데이터가 제한적일 때 |

**면접 포인트**

**"도메인 차이가 크면 전이학습이 오히려 해로울 수 있다"** 는 점을 아는지가 갈림길이다. ImageNet은 자연 이미지인데 내 데이터가 의료 영상이나 센서 신호라면, 앞 층의 저수준 특징은 여전히 쓸모 있지만 뒤 층의 고수준 특징은 맞지 않는다. 이럴 때는 뒤쪽 층을 더 많이 학습시키거나, 같은 도메인으로 사전학습된 모델을 찾는다.

파인튜닝 시 **학습률을 사전학습 때보다 훨씬 낮게** 잡아야 하는 이유도 준비한다. 큰 학습률을 쓰면 애써 배운 특징이 초반 몇 스텝에 망가진다(catastrophic forgetting).

---

### 학습률 스케줄링

**직관**

처음에는 크게 움직여 대략적인 위치를 찾고, 나중에는 작게 움직여 정밀하게 자리를 잡는다. 학습 내내 같은 학습률을 쓰면 초반이 느리거나 후반에 최소점 주변을 맴돈다.

**주요 스케줄**

| 방식 | 설명 |
|------|------|
| Step Decay | 정해진 에폭마다 학습률을 일정 비율로 낮춤 |
| Cosine Annealing | 코사인 곡선을 따라 부드럽게 감소 |
| Warmup | 초반 몇 에폭 동안 학습률을 0에서 목표치까지 올림 |
| ReduceLROnPlateau | 검증 성능이 정체되면 낮춤 |
| One-Cycle | 올렸다가 내리는 한 사이클 |

**면접 포인트**

**Warmup이 왜 필요한가.** 학습 초기에는 파라미터가 무작위라 기울기가 크고 불안정하다. 여기서 큰 학습률을 쓰면 발산하기 쉽다. 특히 큰 배치나 적응형 옵티마이저(Adam)에서 초기 2차 모멘트 추정이 부정확해 갱신량이 튀는데, Warmup이 이를 막는다. 트랜스포머 학습에서는 사실상 필수다.

---

### 온디바이스 추론과 양자화

**직관**

서버로 이미지를 보내지 않고 기기 안에서 바로 추론하는 것이다. 통신 지연이 없고, 네트워크가 없어도 되고, 개인정보가 기기를 떠나지 않는다. 대신 연산 자원과 메모리, 배터리가 제한된다.

**정의**

- 양자화(Quantization): 가중치와 활성값을 32비트 부동소수(FP32)에서 8비트 정수(INT8) 같은 낮은 정밀도로 표현한다. 모델 크기가 1/4로 줄고, 정수 연산 가속기를 쓸 수 있어 속도가 오른다.

**양자화 방식**

| 방식 | 설명 | 정확도 손실 |
|------|------|-------------|
| 학습 후 동적 양자화 | 가중치만 미리, 활성값은 추론 중 | 작음. 가장 간단 |
| 학습 후 정적 양자화 | 대표 데이터로 활성값 범위도 미리 계산(캘리브레이션) | 중간 |
| 양자화 인식 학습(QAT) | 학습 중에 양자화 오차를 시뮬레이션 | 가장 작음. 재학습 필요 |

**핵심 수식**

대칭 양자화:

```
q = round(x / s),    s = max(|x|) / (2^(b-1) - 1)
```

- `x`: 원래 실수 값
- `s`: 스케일. 실수 범위를 정수 범위로 매핑하는 비율
- `b`: 비트 수 (INT8이면 8)
- `q`: 양자화된 정수

**모바일 추론 런타임**

| 플랫폼 | 런타임 |
|--------|--------|
| iOS | Core ML |
| Android | TensorFlow Lite, NNAPI |
| 공통 | ONNX Runtime, PyTorch Mobile / ExecuTorch |

**면접 포인트**

3D 계측 논문들이 "모바일에서 실시간"을 주장하는 근거를 물어볼 때 이 지식이 필요하다. 복잡한 3D 복원을 거치지 않고 키포인트와 깊이 값만으로 치수를 계산하는 설계가 **연산량 자체를 줄인** 접근이라는 점이 핵심이다. 양자화 같은 사후 최적화보다 앞선 단계의 판단이다.

### 트랜스포머 개요

**직관**

CNN은 가까운 픽셀끼리만 먼저 보고 층을 쌓아 가며 시야를 넓힌다. 트랜스포머는 처음부터 **모든 위치가 모든 위치를 본다.** 각 토큰이 "다른 어느 토큰을 얼마나 참고할지"를 계산해 가중 평균을 내는데, 이것이 어텐션이다.

**정의**

셀프 어텐션과 위치별 피드포워드 층을 쌓은 구조다. 순환 구조 없이 시퀀스를 병렬 처리할 수 있어 학습이 빠르고, 긴 의존 관계를 직접 연결한다.

**핵심 수식**

스케일드 닷프로덕트 어텐션:

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

- `Q`(Query): 지금 위치가 "무엇을 찾고 있는가"
- `K`(Key): 각 위치가 "무엇을 갖고 있는가"
- `V`(Value): 실제로 가져올 내용
- `d_k`: 키 벡터의 차원. `√d_k`로 나누는 이유는 차원이 커지면 내적값이 커져 소프트맥스가 한쪽으로 쏠리고 기울기가 작아지기 때문이다

**주요 파생**

| 모델 | 영역 |
|------|------|
| BERT | 인코더만. 문장 이해, 임베딩 |
| GPT 계열 | 디코더만. 텍스트 생성 |
| Sentence-BERT | 문장 임베딩 특화. 문장 간 유사도 계산 |
| ViT | 이미지를 패치로 잘라 트랜스포머에 입력 |
| Swin Transformer | 윈도 기반 어텐션으로 연산량을 줄인 비전 트랜스포머 |

**면접 포인트**

T01 논문에서 메타데이터 벡터화에 **Sentence-BERT**를 썼다. 일반 BERT의 출력을 그대로 평균내면 문장 유사도가 잘 안 나오는데, Sentence-BERT는 문장 쌍으로 학습해 코사인 유사도가 의미를 갖도록 만든 모델이다. "왜 그냥 BERT가 아니라 Sentence-BERT인가"라는 질문이 나올 수 있다.

어텐션의 연산 복잡도가 시퀀스 길이의 제곱(O(n²))이라는 점도 알아 둔다. 이것이 긴 문서나 고해상도 이미지에서 병목이 되고, Swin의 윈도 어텐션 같은 우회책이 나온 이유다.

## 예상 질문

#### Q001. CNN이 완전연결 신경망보다 이미지에 적합한 이유가 무엇입니까? 🟢

**의도:** 가장 기본적인 질문이다. 파라미터 수만 말하는지, 귀납적 편향까지 말하는지로 수준이 갈린다.

**답변:** 두 가지 성질 때문입니다. 첫째는 국소 연결성입니다. 이미지에서 의미 있는 패턴은 대개 가까운 픽셀들 사이에서 만들어지므로, 작은 영역만 보는 필터로 충분합니다. 둘째는 가중치 공유입니다. 같은 필터를 이미지 전체에 적용하기 때문에 파라미터가 크게 줄고, 같은 패턴이 어느 위치에 있어도 인식할 수 있습니다. 완전연결층은 이 두 성질이 없어서, 왼쪽에 있는 고양이와 오른쪽에 있는 고양이를 따로 배워야 하고 파라미터도 감당이 안 됩니다.

**꼬리질문:** 그럼 위치 정보 자체가 중요한 과제에서는 CNN이 불리한가요?

#### Q002. 배치 정규화가 학습을 안정시키는 원리를 설명해 주세요. 🟢

**의도:** 정의를 외웠는지, 최근의 해석 논쟁까지 아는지 본다.

**답변:** 각 층의 입력을 미니배치 단위로 평균 0, 분산 1로 맞추고, 학습 가능한 스케일과 시프트로 다시 조정합니다. 원 논문은 앞 층이 갱신되면서 뒤 층이 받는 입력 분포가 계속 바뀌는 문제, 즉 내부 공변량 변화를 줄인다고 설명했습니다. 이후 연구에서는 손실 지형을 더 매끄럽게 만들어 큰 학습률을 안정적으로 쓸 수 있게 하는 효과가 더 크다는 분석이 나왔습니다. 실무적으로는 학습률을 키울 수 있고 초기값에 덜 민감해진다는 점이 체감됩니다.

**꼬리질문:** 추론할 때는 미니배치가 없는데 어떻게 정규화합니까?

#### Q003. 배치 크기를 아주 작게 잡아야 하는 상황이면 무엇을 바꾸시겠습니까? 🟡

**의도:** 고해상도 분할·검출에서 실제로 겪는 문제를 다뤄 봤는지 확인한다.

**답변:** 배치 정규화를 Group Norm이나 Layer Norm으로 바꿉니다. 배치 정규화는 미니배치의 평균과 분산으로 정규화하는데, 배치가 2나 4면 그 통계량 추정이 매우 불안정해서 오히려 학습을 방해합니다. Group Norm은 채널을 몇 개 그룹으로 묶어 정규화하기 때문에 배치 크기와 무관합니다. 그다음으로는 기울기 누적을 씁니다. 작은 배치로 여러 번 순전파·역전파를 하고 기울기를 모아서 한 번에 갱신하면 큰 배치 효과를 냅니다. 메모리는 그대로 두고 학습 안정성만 가져오는 방법입니다.

**꼬리질문:** 기울기 누적을 쓰면 배치 정규화 문제도 같이 해결됩니까?

#### Q004. 잔차 연결이 왜 깊은 망을 학습 가능하게 만듭니까? 🟢

**의도:** ResNet을 이름만 아는지, 원리를 아는지 확인한다.

**답변:** 역전파에서 기울기가 곱해지며 전달되는데, 층이 깊으면 이 곱이 0에 수렴해 앞쪽 층이 학습되지 않습니다. 잔차 연결은 층의 출력에 입력을 그대로 더하기 때문에, 미분하면 기울기 경로에 1이 더해집니다. 곱셈 경로 옆에 덧셈 경로가 하나 생기는 셈이라 기울기가 소멸하지 않고 앞까지 전달됩니다. 또 하나는 최적화 관점인데, 그 블록이 아무것도 하지 않는 것이 최선이면 가중치를 0으로 만들면 되기 때문에 항등 사상을 배우기가 쉬워집니다. 그래서 깊게 쌓아도 최소한 얕은 망만큼은 보장됩니다.

**꼬리질문:** 입력과 출력의 채널 수가 다르면 어떻게 더합니까?

#### Q005. 모바일에서 돌려야 한다면 어떤 순서로 모델을 줄이시겠습니까? 🟡

**의도:** 경량화를 양자화 하나로만 아는지, 효과 크기 순으로 판단하는지 본다.

**답변:** 구조 설계를 가장 먼저 봅니다. 표준 합성곱을 깊이별 분리 합성곱으로 바꾸면 커널이 3×3일 때 연산량이 대략 9분의 1로 줄어서, 다른 어떤 방법보다 효과가 큽니다. 그다음이 입력 해상도입니다. 해상도를 절반으로 줄이면 연산량이 4분의 1이 되는데, 작은 대상을 놓치지 않는 선에서 얼마나 줄일 수 있는지 실험으로 찾습니다. 그다음이 양자화입니다. INT8로 바꾸면 모델 크기가 4분의 1이 되고 정수 연산 가속기를 쓸 수 있습니다. 가지치기는 재학습이 필요하고 얻는 것에 비해 손이 많이 가서 마지막에 둡니다. 다만 3D 계측 과제에서는 이런 사후 최적화보다, 복잡한 3차원 복원을 거치지 않는 파이프라인 설계 자체가 연산량을 줄인 결정적 요인이었습니다.

**꼬리질문:** 양자화했을 때 정확도가 많이 떨어지면 어떻게 하십니까?

#### Q006. 깊이별 분리 합성곱이 연산량을 얼마나 줄이는지 계산해 보실 수 있나요? 🟡

**의도:** 수식을 외웠는지가 아니라, 왜 줄어드는지 구조적으로 아는지 본다.

**답변:** 표준 합성곱은 커널 크기 제곱에 입력 채널과 출력 채널을 모두 곱한 만큼 연산이 듭니다. 깊이별 분리 합성곱은 이걸 두 단계로 나눕니다. 먼저 채널별로 따로 공간 합성곱을 하고, 그다음 1×1 합성곱으로 채널을 섞습니다. 연산량 비율은 출력 채널 수의 역수에 커널 크기 제곱의 역수를 더한 값이 됩니다. 커널이 3×3이고 출력 채널이 256이면 대략 0.115, 즉 9분의 1 수준입니다. 채널이 많을수록 절감 효과가 커집니다.

**꼬리질문:** 연산량이 9분의 1인데 실제 추론 속도도 9배 빨라집니까?

#### Q007. 전이학습이 오히려 해로운 경우가 있습니까? 🟡

**의도:** 전이학습을 만능으로 여기는지, 조건을 아는지 본다.

**답변:** 도메인 차이가 크면 그렇습니다. ImageNet은 자연 이미지인데 대상이 의료 영상이나 센서 신호처럼 성질이 다르면, 앞쪽 층의 저수준 특징은 여전히 쓸모 있지만 뒤쪽 층의 고수준 특징은 오히려 방해가 됩니다. 이럴 때는 뒤쪽 층을 더 많이 학습시키거나 같은 도메인으로 사전학습된 모델을 찾습니다. 그리고 학습률을 처음부터 크게 잡으면 사전학습으로 얻은 특징이 초반 몇 스텝에 망가져 버립니다. 파인튜닝할 때는 사전학습 때보다 훨씬 낮은 학습률을 쓰고, 필요하면 앞 층과 뒤 층에 다른 학습률을 줍니다.

**꼬리질문:** 도메인이 다른지 아닌지를 미리 어떻게 판단하십니까?

#### Q008. Adam과 SGD 중 무엇을 쓰시겠습니까? 🟡

**의도:** 기본값을 그대로 쓰는지, 선택 근거가 있는지 본다.

**답변:** 기준선을 빠르게 잡을 때는 Adam을 씁니다. 학습률에 덜 민감하고 기본값으로도 대체로 수렴하기 때문입니다. 다만 이미지 분류 같은 과제에서는 잘 튜닝된 SGD와 모멘텀이 일반화 성능이 더 좋게 나오는 경우가 많아서, 최종 모델을 만들 때는 SGD에 코사인 스케줄을 붙여 다시 학습해 비교합니다. 트랜스포머 계열은 AdamW에 Warmup을 쓰는 것이 사실상 표준이라 그쪽을 따릅니다.

**꼬리질문:** Adam이 일반화가 나쁘다는 건 왜 그렇다고 보십니까?

#### Q009. 학습이 전혀 진행되지 않을 때 무엇부터 확인하시겠습니까? 🟡

**의도:** 실제로 디버깅을 해 본 사람인지 본다. 순서가 있는지가 중요하다.

**답변:** 먼저 아주 작은 데이터, 예를 들어 샘플 열 개로 과적합이 되는지 봅니다. 여기서도 손실이 안 떨어지면 모델이나 손실함수, 데이터 파이프라인에 버그가 있는 것이라 코드부터 봅니다. 손실이 0으로 떨어지면 모델 자체는 학습 가능한 상태이므로 그다음은 학습률을 의심합니다. 너무 크면 발산하고 너무 작으면 안 움직입니다. 그다음이 데이터입니다. 레이블이 잘못 붙었는지, 정규화가 빠졌는지, 입력 범위가 이상한지를 확인합니다. 마지막으로 초기화와 활성함수를 봅니다. 기울기가 층별로 어떻게 흐르는지 실제로 찍어 보면 어디서 죽는지 보입니다.

**꼬리질문:** 손실이 NaN이 되는 경우는 무엇을 의심하십니까?

#### Q010. 데이터 증강을 고를 때 어떤 기준을 쓰십니까? 🟡

**의도:** 관행대로 다 넣는지, 과제의 불변성을 이해하는지 본다.

**답변:** 그 변형을 가해도 정답이 바뀌지 않아야 한다는 것이 기준입니다. 좌우 반전은 일반 물체 분류에서는 괜찮지만 문자 인식에서는 안 됩니다. 특히 치수 측정 과제에서는 무작위 스케일 변환을 쓸 수 없습니다. 실제 물리적 크기를 재는 것이 목적인데 크기를 임의로 바꿔 버리면 과제 자체가 무의미해집니다. 그래서 어떤 변형이 실제 촬영 환경에서 일어날 수 있는 변동인지를 먼저 정리하고, 그 범위 안에서만 증강을 씁니다. 조명 변화나 약간의 회전은 현장에서 실제로 생기는 변동이라 넣었습니다.

**꼬리질문:** 증강을 얼마나 세게 걸어야 하는지는 어떻게 정하십니까?

#### Q011. Sentence-BERT를 쓰신 이유가 무엇입니까? 일반 BERT와 무엇이 다릅니까? 🟡

**의도:** T01 논문에서 쓴 도구를 이유 있게 골랐는지 확인한다.

**답변:** 일반 BERT는 마스크 언어 모델로 학습돼서, 출력 토큰 벡터를 평균내 문장 벡터로 쓰면 문장 간 코사인 유사도가 의미를 제대로 반영하지 못합니다. Sentence-BERT는 문장 쌍을 입력으로 받아 두 문장의 유사도를 학습하도록 구조와 목적함수를 바꾼 모델이라, 나온 벡터를 코사인 유사도로 바로 비교할 수 있습니다. 상품 메타데이터로 상품 간 관계를 예측하는 것이 목적이었기 때문에, 문장 벡터끼리의 거리가 의미를 갖는 것이 중요했습니다.

**꼬리질문:** 한국어와 영어가 섞인 데이터였는데 그건 어떻게 처리하셨습니까?

#### Q012. 최근 CNN 대신 트랜스포머를 많이 쓰는데 어떻게 보십니까? 🔴

**의도:** 최신 동향을 따라가는지, 그리고 유행을 무비판적으로 받아들이는지 본다.

**답변:** 데이터 규모에 따라 다르다고 봅니다. 비전 트랜스포머는 CNN이 가진 국소성이나 평행이동 등변성 같은 귀납적 편향이 없어서, 데이터가 아주 많을 때 그 제약이 없는 편이 유리하게 작용합니다. 반대로 데이터가 제한적이면 CNN의 편향이 오히려 도움이 됩니다. 제가 다룬 과제들은 직접 수집한 데이터라 규모가 크지 않았고 모바일 제약도 있어서 CNN 계열이 맞았습니다. 다만 ConvNeXt처럼 트랜스포머의 설계 요소를 CNN에 가져와 성능을 끌어올린 연구도 있어서, 구조 자체보다 어떤 설계 요소가 효과가 있는지를 보는 편입니다.

**꼬리질문:** 그럼 지금 같은 과제를 다시 한다면 어떤 백본을 쓰시겠습니까?

#### Q013. 기울기 소실과 기울기 폭발을 각각 어떻게 막습니까? 🟢

**의도:** 대응책을 체계적으로 정리해 뒀는지 본다.

**답변:** 기울기 소실은 활성함수를 ReLU 계열로 바꾸는 것, He 초기화를 쓰는 것, 배치 정규화를 넣는 것, 잔차 연결을 두는 것으로 대응합니다. 시그모이드의 미분값이 최대 0.25라 층을 여러 번 지나면 급격히 줄어드는 것이 원인이므로, 미분값이 1인 구간을 만들어 주는 것이 핵심입니다. 기울기 폭발은 기울기 클리핑으로 노름에 상한을 두고, 학습률을 낮추고, 초기화를 조정합니다. 순환 신경망에서 특히 자주 생기는 문제입니다.

**꼬리질문:** He 초기화와 Xavier 초기화의 차이는 무엇입니까?

#### Q014. Warmup은 왜 필요합니까? 🟡

**의도:** 스케줄링을 관행으로 쓰는지 이유를 아는지 본다.

**답변:** 학습 초기에는 파라미터가 무작위 상태라 기울기가 크고 방향도 불안정합니다. 여기서 목표 학습률을 그대로 쓰면 발산하기 쉽습니다. 특히 Adam 같은 적응형 옵티마이저는 2차 모멘트 추정값이 초반에 부정확해서 갱신 크기가 크게 튀는데, Warmup으로 학습률을 0에서 천천히 올리면 그 구간을 안전하게 넘길 수 있습니다. 배치를 크게 잡을 때도 학습률을 함께 키우게 되는데, 이때 Warmup이 없으면 초반에 무너집니다.

**꼬리질문:** Warmup 구간은 어느 정도로 잡으십니까?

#### Q015. 수용영역이라는 개념이 실제 설계에 어떻게 쓰입니까? 🟡

**의도:** 개념을 알고만 있는지, 설계 판단에 쓰는지 본다.

**답변:** 출력의 한 픽셀이 원본에서 얼마나 넓은 영역을 보고 있는가인데, 과제가 요구하는 맥락 크기와 맞춰야 합니다. 작은 결함을 찾는 과제에서 수용영역이 지나치게 크면 대상이 배경 정보에 묻히고, 전체 형상을 봐야 하는 과제에서 너무 작으면 부분만 보고 판단하게 됩니다. 분할 과제에서는 딜레마가 생기는데, 넓은 맥락을 보려면 다운샘플링을 해야 하지만 그러면 픽셀 단위 경계가 뭉개집니다. U-Net의 스킵 연결, DeepLab의 확장 합성곱, HRNet의 고해상도 유지가 모두 이 딜레마에 대한 서로 다른 해법입니다.

**꼬리질문:** 세 가지 중에서 키포인트 검출에는 어느 것이 맞다고 보십니까?
