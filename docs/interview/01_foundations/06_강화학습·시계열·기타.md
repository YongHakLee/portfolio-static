## 개념 목록

### 강화학습의 구성 요소

**직관**

지도학습은 정답이 적힌 문제집으로 배운다. 강화학습은 정답 없이 **행동해 보고 결과로 받은 보상**으로 배운다. 게임을 하면서 점수가 오르는 행동을 늘리고 점수가 깎이는 행동을 줄이는 식이다.

어려운 점은 **보상이 늦게 온다**는 것이다. 체스에서 30수 전의 한 수가 패배의 원인이었을 수 있는데, 어느 수가 잘못이었는지 알기 어렵다. 이를 신용 할당 문제(credit assignment problem)라고 한다.

**정의**

| 요소 | 기호 | 설명 |
|------|------|------|
| 에이전트(Agent) | — | 행동을 결정하는 주체 |
| 환경(Environment) | — | 에이전트가 상호작용하는 대상 |
| 상태(State) | s | 현재 상황의 표현 |
| 행동(Action) | a | 에이전트가 선택할 수 있는 것 |
| 보상(Reward) | r | 행동의 결과로 받는 즉각적 신호 |
| 정책(Policy) | π | 상태에서 행동을 고르는 규칙. `π(a\|s)` |
| 가치(Value) | V, Q | 앞으로 받을 보상의 총합에 대한 기댓값 |

**학습의 흐름**

```
상태 s_t 관찰 → 정책에 따라 행동 a_t 선택 → 보상 r_t와 다음 상태 s_{t+1} 받음
→ 이 경험 (s_t, a_t, r_t, s_{t+1})으로 정책이나 가치함수 갱신 → 반복
```

**면접 포인트**

**지도학습과의 세 가지 차이**를 말할 수 있으면 좋다. 첫째, 정답 대신 보상만 있다. 둘째, 보상이 지연된다. 셋째, **데이터가 독립적이지 않다.** 에이전트의 행동이 다음에 보게 될 데이터를 결정하므로, 연속된 경험은 강하게 상관돼 있다. 이 세 번째 성질이 경험 리플레이가 필요한 이유다.

### 마르코프 결정 과정

**직관**

"현재 상태만 알면 과거는 몰라도 된다"는 가정이다. 체스에서 지금 판을 보면 어떤 순서로 그 판이 됐는지 몰라도 다음 수를 정할 수 있다.

**정의**

MDP는 다섯 개 조로 정의된다: `(S, A, P, R, γ)`

- `S`: 상태 집합
- `A`: 행동 집합
- `P(s'|s,a)`: 상태 전이 확률
- `R(s,a)`: 보상 함수
- `γ`: 할인율 (0~1)

**마르코프 성질**

```
P(s_{t+1} | s_t, a_t, s_{t-1}, a_{t-1}, ...) = P(s_{t+1} | s_t, a_t)
```

다음 상태는 **현재 상태와 행동에만** 의존한다.

**할인율 γ의 의미**

미래 보상을 현재 가치로 환산할 때 곱하는 비율이다.

```
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ...
```

- γ가 0에 가까우면 근시안적(즉각적 보상만 중시)
- γ가 1에 가까우면 장기적
- γ < 1이어야 무한 시간에서 합이 발산하지 않는다

**면접 포인트**

**실제 문제에서 마르코프 성질이 성립하지 않는 경우**를 알면 좋다. 화면 한 장만 보면 공이 어느 방향으로 움직이는지 모른다. 그래서 Atari 실험에서는 최근 4프레임을 겹쳐 하나의 상태로 쓴다. 상태 정의를 어떻게 하느냐가 문제 난이도를 결정한다.

### 가치함수와 벨만 방정식

**직관**

가치함수는 "이 상태(또는 이 상태에서 이 행동)가 앞으로 얼마나 좋은가"를 숫자로 매긴 것이다. 좋다는 것은 앞으로 받을 보상의 총합이 크다는 뜻이다.

벨만 방정식은 이를 **재귀적으로** 표현한다. "지금의 가치 = 즉시 받는 보상 + 다음 상태의 가치"다.

**정의**

| 함수 | 정의 |
|------|------|
| 상태가치 `V^π(s)` | 정책 π를 따를 때 상태 s에서 시작해 받을 보상 총합의 기댓값 |
| 행동가치 `Q^π(s,a)` | 상태 s에서 행동 a를 하고 그 뒤 π를 따를 때의 기댓값 |

**핵심 수식**

벨만 기대 방정식:

```
Q^π(s, a) = E[ r + γ · Q^π(s', a') ]
```

벨만 최적 방정식:

```
Q*(s, a) = E[ r + γ · max_{a'} Q*(s', a') ]
```

- `Q*`: 최적 정책의 행동가치
- `max_{a'}`: 다음 상태에서 가능한 행동 중 가장 좋은 것을 고른다

**읽는 법**: 최적 Q값은 "지금 받는 보상 + 할인된 다음 상태의 최선의 Q값"이다. 이 재귀 관계가 Q-learning의 갱신식이 된다.

**면접 포인트**

**벨만 방정식이 왜 중요한가**는 "미래 전체를 계산하지 않고 한 단계만 보고 갱신할 수 있게 해 주기 때문"이다. 끝까지 시뮬레이션하지 않고도 학습이 가능해진다. 이것이 시간차 학습(TD learning)의 기반이다.

### Q-learning

**직관**

각 (상태, 행동) 쌍의 Q값을 표에 적어 두고, 경험할 때마다 조금씩 갱신한다. 갱신 방향은 "지금 알고 있는 Q값"과 "실제로 경험해 보니 이 정도였다는 추정값"의 차이다.

**핵심 수식**

```
Q(s,a) ← Q(s,a) + α [ r + γ·max_{a'} Q(s',a') - Q(s,a) ]
                     └────────── TD 오차 ──────────┘
```

- `α`: 학습률
- `r + γ·max_{a'} Q(s',a')`: TD 타깃. 실제 경험에 기반한 새 추정
- `Q(s,a)`: 현재 추정
- 둘의 차이가 TD 오차다

**off-policy라는 성질**

Q-learning은 **행동할 때 쓰는 정책과 학습하는 정책이 다르다.** 행동은 탐험을 위해 무작위성을 섞지만, 갱신할 때는 `max`를 취해 최적 정책을 학습한다. 이 성질 덕분에 **과거의 경험을 재사용할 수 있다.** 경험 리플레이가 가능한 이유가 이것이다.

**SARSA와의 차이**

```
Q-learning:  타깃 = r + γ·max_{a'} Q(s',a')      (off-policy)
SARSA:       타깃 = r + γ·Q(s',a')               (on-policy, 실제 취한 a'를 씀)
```

**면접 포인트**

**off-policy와 경험 리플레이의 연결**이 T10 논문을 이해하는 핵심이다. on-policy 방법은 현재 정책으로 모은 데이터만 쓸 수 있어서 과거 경험을 저장해 재사용하는 것이 원리적으로 맞지 않다. Q-learning 계열이 off-policy이기 때문에 리플레이 메모리가 성립한다.

### DQN과 타깃 네트워크

**직관**

상태가 이미지처럼 크면 Q값 표를 만들 수 없다. 픽셀 조합의 수가 천문학적이기 때문이다. DQN은 표 대신 **신경망으로 Q함수를 근사한다.**

문제는 신경망을 쓰면 학습이 불안정해진다는 것이다. 두 가지 장치로 이를 해결했다: **경험 리플레이**와 **타깃 네트워크**.

**정의**

```
손실 = E[ ( r + γ·max_{a'} Q_target(s',a'; θ⁻) - Q(s,a; θ) )² ]
```

- `θ`: 학습되는 온라인 네트워크의 파라미터
- `θ⁻`: **타깃 네트워크**의 파라미터. 주기적으로 θ를 복사해 오지만 그 사이에는 고정

**타깃 네트워크가 필요한 이유**

타깃 네트워크 없이 같은 네트워크로 타깃을 계산하면, 갱신할 때마다 타깃도 함께 움직인다. **움직이는 과녁을 쏘는 셈**이라 발산하기 쉽다. 타깃을 일정 기간 고정하면 지도학습처럼 안정된 목표가 생긴다.

**DQN 계열의 발전**

| 변형 | 개선점 |
|------|--------|
| Double DQN | Q값 과대추정 완화 — 행동 선택과 평가를 분리 |
| Dueling DQN | 상태가치와 이점(advantage)을 분리해 추정 |
| Prioritized Replay | 중요한 경험을 더 자주 샘플링 |
| Noisy Net | 탐험을 파라미터 노이즈로 |
| Rainbow | 위 기법들을 통합 |

**Double DQN의 과대추정 문제**

`max` 연산이 문제다. Q값에 잡음이 있을 때 최댓값을 취하면 잡음이 큰 쪽이 뽑혀 체계적으로 과대평가된다. Double DQN은 행동을 온라인 네트워크로 고르고 그 행동의 가치는 타깃 네트워크로 평가해 이를 완화한다.

```
Double DQN 타깃 = r + γ · Q_target( s', argmax_{a'} Q_online(s', a') )
```

**면접 포인트**

**"DQN의 두 가지 안정화 장치가 무엇인가"** 는 단골 질문이다. 경험 리플레이(데이터 상관 제거)와 타깃 네트워크(목표 고정)를 답하고, 각각이 어떤 불안정성을 해결하는지 말한다. T10 논문이 리플레이 쪽을 건드린 연구이므로 이 구도를 먼저 잡아 둬야 한다.

### 경험 리플레이

**직관**

에이전트가 겪은 경험 `(s, a, r, s')`을 버퍼에 저장해 두고, 학습할 때 **무작위로 섞어 꺼내 쓴다.**

두 가지 문제를 동시에 푼다. 첫째, 연속된 경험은 강하게 상관돼 있는데(방금 본 화면과 지금 화면은 거의 같다), 무작위 샘플링이 이 상관을 깬다. 둘째, 한 번 겪은 경험을 여러 번 재사용할 수 있어 데이터 효율이 올라간다.

**정의**

크기 N의 순환 버퍼에 전이(transition)를 저장하고, 학습 시 미니배치를 균등 무작위로 추출한다.

```
버퍼 D = {(s₁,a₁,r₁,s'₁), ..., (s_N,a_N,r_N,s'_N)}
학습: D에서 배치를 균등 샘플링해 손실 계산
```

**설계 파라미터**

| 파라미터 | 영향 |
|----------|------|
| 버퍼 크기 | 크면 오래된 경험까지 유지(다양성↑, 현재 정책과 괴리↑) |
| 배치 크기 | 기울기 안정성 |
| 학습 시작 시점 | 버퍼가 어느 정도 찬 뒤 시작 |
| 갱신 빈도 | 한 스텝당 몇 번 학습할지 |

**한계**

- **모든 경험을 똑같이 취급한다.** 학습에 도움이 되는 경험과 이미 잘 아는 경험이 같은 확률로 뽑힌다
- **오래된 경험은 현재 정책과 동떨어져 있을 수 있다.** 버퍼가 너무 크면 낡은 경험이 학습을 방해한다
- 메모리를 많이 쓴다

**면접 포인트**

**이 두 한계가 T10 논문의 출발점이다.** 논문 제목이 "Double Replay Memory"이고, 초록에 "중요한 전이와 새로운 전이를 동시에 활용한다"고 되어 있다. 즉 **하나의 버퍼로는 '중요함'과 '새로움'을 동시에 만족시킬 수 없다**는 문제의식이다.

우선순위 리플레이는 중요한 경험을 자주 뽑지만 그러면 새로운 경험이 상대적으로 덜 뽑히고, 균등 샘플링은 새로움은 보장하지만 중요도를 반영하지 못한다. 버퍼를 둘로 나누면 각각을 따로 관리할 수 있다는 것이 논문의 착상으로 읽힌다. 원문에서 이 구조를 확인해야 하지만, 이 배경을 알고 읽으면 방법론이 훨씬 명확해진다.

### 우선순위 경험 리플레이

**직관**

TD 오차가 큰 경험은 "예상과 많이 달랐던 경험", 즉 아직 잘 모르는 상황이다. 이런 경험을 더 자주 학습하면 효율이 오른다.

**핵심 수식**

샘플링 확률:

```
P(i) = pᵢ^α / Σⱼ pⱼ^α
```

- `pᵢ`: 전이 i의 우선순위. 보통 `|TD 오차| + ε`
- `α`: 우선순위 반영 강도. 0이면 균등 샘플링, 1이면 완전히 우선순위대로

**중요도 샘플링 보정**

균등하지 않게 뽑으면 기댓값이 편향된다. 이를 가중치로 보정한다.

```
wᵢ = ( 1 / (N · P(i)) )^β
```

- `β`: 보정 강도. 학습 초기에는 작게 두고 점차 1로 올린다(annealing)
- 자주 뽑히는(P가 큰) 샘플에 작은 가중치를 줘 편향을 상쇄한다

**부작용**

- TD 오차가 큰 경험에 편중되면 **다양성이 줄어든다**
- 잡음이 큰 전이(운 나쁘게 큰 오차가 난 경우)가 계속 뽑힐 수 있다
- 우선순위 계산과 관리에 비용이 든다(합 트리 자료구조 사용)

**면접 포인트**

**"우선순위 리플레이가 있는데 왜 버퍼를 둘로 나누는가"** 가 T10에 대한 가장 날카로운 질문이다. 답의 방향은 위 부작용에 있다. 우선순위 리플레이는 중요도는 반영하지만 다양성과 최신성을 희생한다. 두 버퍼를 두면 한쪽은 중요한 경험을, 다른 쪽은 최근 경험을 담당하게 해 트레이드오프를 분리할 수 있다. 정확한 논지는 원문에서 확인해야 한다.

### 탐험과 활용

**직관**

새 식당을 시도할지(탐험), 아는 맛집에 갈지(활용)의 딜레마다. 탐험만 하면 좋은 것을 알아도 안 쓰고, 활용만 하면 더 좋은 것을 영영 못 찾는다.

**주요 전략**

| 전략 | 방법 |
|------|------|
| ε-greedy | 확률 ε로 무작위 행동, 1−ε로 최선의 행동. ε를 점차 줄임 |
| Boltzmann | Q값에 비례한 확률로 행동 선택 (소프트맥스) |
| UCB | 불확실성이 큰 행동에 보너스를 줌 |
| Noisy Net | 네트워크 가중치에 학습 가능한 노이즈를 넣어 탐험을 학습 |
| 내재적 보상 | 새로운 상태 방문 자체에 보상을 줌 (curiosity) |

**면접 포인트**

**ε 감쇠 스케줄**이 실무 감각을 보여 준다. 초기에는 ε=1(완전 무작위)에서 시작해 학습이 진행되며 0.01~0.1까지 줄인다. 완전히 0으로 만들지 않는 이유는 환경이 변하거나 아직 못 본 상태가 남아 있을 수 있어서다.

### 시계열 데이터의 특성

**직관**

시계열은 순서가 의미를 갖는 데이터다. 데이터를 섞으면 정보가 파괴된다. 그래서 일반적인 머신러닝 관행 중 상당수(무작위 분할, 무작위 교차검증)를 그대로 쓸 수 없다.

**구성 요소**

| 성분 | 설명 |
|------|------|
| 추세(Trend) | 장기적 상승·하락 |
| 계절성(Seasonality) | 주기적 반복 |
| 순환(Cycle) | 주기가 일정하지 않은 변동 |
| 불규칙(Noise) | 설명되지 않는 변동 |

**정상성(stationarity)**

평균·분산·자기공분산이 시간에 따라 변하지 않는 성질이다. 많은 통계 모형(ARIMA 등)이 정상성을 가정한다. 비정상 시계열은 차분이나 로그 변환으로 정상화한다.

**시계열 검증**

```
잘못된 방법: 무작위로 학습/검증 분할  → 미래 정보가 과거 학습에 새어 들어감
올바른 방법: 시간 순 분할 (walk-forward)
   [학습 1~100] [검증 101~120]
   [학습 1~120] [검증 121~140]
   ...
```

**면접 포인트**

**금융 시계열의 특수성**을 알면 좋다. 수익률은 대체로 정상에 가깝지만 **변동성 군집(volatility clustering)** 이 있어 변동이 큰 시기와 작은 시기가 뭉쳐 나타난다. 또 분포의 꼬리가 정규분포보다 두껍다(fat tail). 정규분포를 가정한 위험 계산이 실제 위험을 과소평가하는 이유다.

### 이동평균과 기술적 지표

**직관**

가격은 잡음이 많아 그대로 보면 방향을 알기 어렵다. 이동평균은 최근 N일 평균을 이어 그린 선으로, 잡음을 걷어 내고 추세를 드러낸다.

**핵심 수식**

단순 이동평균(SMA):

```
SMA_t(n) = (1/n) Σ_{i=0}^{n-1} P_{t-i}
```

지수 이동평균(EMA):

```
EMA_t = α·P_t + (1-α)·EMA_{t-1},    α = 2/(n+1)
```

- EMA는 최근 값에 더 큰 가중치를 줘 반응이 빠르다

**주요 기술적 지표**

| 지표 | 계산 | 읽는 법 |
|------|------|---------|
| 골든크로스 | 단기 이동평균이 장기 이동평균을 상향 돌파 | 상승 전환 신호로 해석 |
| 데드크로스 | 단기가 장기를 하향 돌파 | 하락 전환 신호 |
| MACD | 단기 EMA − 장기 EMA, 그리고 그 신호선 | 추세 강도와 전환 |
| RSI | 일정 기간 상승폭과 하락폭의 비율 (0~100) | 70 이상 과매수, 30 이하 과매도 |
| 볼린저 밴드 | 이동평균 ± k×표준편차 | 밴드 이탈로 변동성 판단 |

**핵심 한계: 후행성**

이동평균은 **과거 데이터의 평균**이므로 본질적으로 늦다. 기간 n이 길수록 안정적이지만 더 늦고, 짧을수록 빠르지만 거짓 신호가 많다. 이 트레이드오프는 원리적으로 피할 수 없다.

**면접 포인트**

**"기술적 지표가 통계적으로 근거가 있는가"** 라는 회의적 질문이 올 수 있다. 정직한 답은 **이론적 근거는 약하고 경험적으로 쓰여 온 도구**라는 것이다. 효율적 시장 가설에 따르면 과거 가격에서 초과수익을 얻을 수 없다. T11 논문의 가치는 "이 지표가 맞다"를 주장하는 데 있다기보다, **널리 쓰이는 패턴을 수치로 정의하고 그 성과를 체계적으로 검증했다**는 데 있다고 보는 편이 방어하기 쉽다.

### 차트 패턴 (헤드앤숄더)

**직관**

가격 그래프에서 세 개의 봉우리가 나타나되, 가운데 봉우리(머리)가 양옆(어깨)보다 높은 모양이다. 사람 상반신 실루엣을 닮아 헤드앤숄더라 부른다. 전통적으로 상승 추세의 끝을 알리는 반전 신호로 해석된다.

**구성 요소**

```
        머리(Head)
         /\
왼어깨   /  \   오른어깨
  /\    /    \    /\
 /  \  /      \  /  \
─────\/────────\/─────  넥라인(Neckline)
```

- **왼쪽 어깨**: 첫 번째 고점 후 하락
- **머리**: 더 높은 고점 후 하락
- **오른쪽 어깨**: 머리보다 낮은 고점
- **넥라인**: 두 저점을 이은 선. 이 선을 하향 돌파하면 패턴 완성으로 본다
- **역헤드앤숄더**: 뒤집힌 모양. 하락 추세의 끝 신호로 해석

**수치적 정의의 어려움**

사람은 그림을 보고 "이건 헤드앤숄더다"라고 판단하지만, 프로그램이 하려면 규칙이 필요하다. 정해야 할 것들:

| 항목 | 결정할 것 |
|------|-----------|
| 고점·저점 탐지 | 몇 봉 기준으로 국소 극값을 잡을 것인가 |
| 머리 조건 | 머리가 양 어깨보다 몇 % 이상 높아야 하는가 |
| 어깨 대칭성 | 두 어깨의 높이 차이를 몇 %까지 허용하는가 |
| 시간 간격 | 세 봉우리 사이 간격이 비슷해야 하는가 |
| 넥라인 기울기 | 수평이어야 하는가, 기울어져도 되는가 |
| 돌파 확인 | 종가 기준인가, 며칠 유지돼야 하는가 |

**이 정의가 곧 연구의 실질**이다. 임계값을 어떻게 잡느냐에 따라 검출되는 패턴 수와 성과가 완전히 달라진다.

**면접 포인트**

**"패턴 정의의 임계값을 데이터에서 최적화했다면 그건 과최적화 아닌가"** 가 가장 날카로운 질문이다. 검출 규칙의 파라미터를 성과가 좋아지는 쪽으로 맞췄다면, 그 성과는 미래에 재현되지 않을 가능성이 크다. T11을 읽을 때 **파라미터를 어떻게 정했는지, 검증 기간과 최적화 기간을 분리했는지**를 반드시 확인해야 한다.

### 백테스팅과 과최적화

**직관**

과거 데이터로 전략을 시뮬레이션해 성과를 보는 것이 백테스팅이다. 문제는 과거에 잘 맞는 규칙을 찾기가 너무 쉽다는 것이다. 파라미터를 이리저리 바꾸다 보면 반드시 과거에 훌륭한 조합이 나오는데, 그것이 미래에도 통한다는 보장은 전혀 없다.

**백테스팅의 함정**

| 함정 | 설명 |
|------|------|
| **선견 편향(look-ahead bias)** | 그 시점에 알 수 없었던 정보를 사용. 예: 종가로 그날 매수 |
| **생존 편향(survivorship bias)** | 상장폐지된 종목을 데이터에서 제외해 성과가 부풀려짐 |
| **과최적화(overfitting)** | 파라미터를 과거에 맞춰 조정 |
| **다중 검정 문제** | 수백 개 전략을 시험하면 우연히 좋은 게 나옴 |
| **거래비용 무시** | 수수료·슬리피지·세금을 빼면 수익이 사라지는 경우가 많음 |
| **유동성 무시** | 실제로는 원하는 가격에 원하는 수량을 못 삼 |

**성과 지표**

| 지표 | 계산 | 의미 |
|------|------|------|
| 누적 수익률 | 최종/초기 − 1 | 총 수익 |
| CAGR | 연환산 복리 수익률 | 기간이 다른 전략 비교 |
| 샤프 비율 | (수익률 − 무위험이자율) / 변동성 | 위험 대비 수익 |
| 최대 낙폭(MDD) | 고점 대비 최대 하락률 | 실제로 버틸 수 있는지 |
| 승률 | 이긴 거래 비율 | 단독으로는 의미 약함 |
| 손익비 | 평균 이익 / 평균 손실 | 승률과 함께 봐야 함 |

**샤프 비율**

```
Sharpe = (R_p - R_f) / σ_p
```

- `R_p`: 포트폴리오 수익률
- `R_f`: 무위험 수익률
- `σ_p`: 수익률의 표준편차

**바른 검증 설계**

```
1. 데이터를 시간 순으로 분리한다: 개발 기간 / 검증 기간 / 최종 테스트 기간
2. 파라미터는 개발 기간에서만 정한다
3. 검증 기간은 파라미터 조정에 쓰지 않는다
4. 거래비용을 보수적으로 반영한다
5. 시험한 전략의 총 개수를 밝힌다 (다중 검정 보정)
6. 워크포워드 분석으로 시간에 따른 안정성을 본다
```

**면접 포인트**

**승률만 높은 전략의 위험**을 지적할 수 있으면 좋다. 승률 90%여도 지는 한 번에 크게 잃으면 전체는 손실이다. 승률과 손익비를 함께 봐야 하고, 최대 낙폭이 실제로 감당 가능한 수준인지가 실용성을 결정한다.

통계 전공자로서 **다중 검정 문제**를 짚으면 인상이 좋다. 수백 개 파라미터 조합을 시험하면 유의수준 5%에서 우연히 유의한 결과가 나오는 것이 당연하다. 이를 보정하지 않은 백테스팅 결과는 신뢰하기 어렵다.

### 블록체인 기초

**직관**

거래 기록을 여러 사람이 나눠 갖고, 새 기록을 추가할 때마다 모두가 검증하는 장부다. 중앙 관리자가 없어도 위조가 어렵다. 각 블록이 앞 블록의 해시를 담고 있어, 중간을 고치면 뒤가 전부 어긋난다.

**핵심 구성**

| 요소 | 설명 |
|------|------|
| 블록 | 거래 묶음 + 이전 블록 해시 + 타임스탬프 + 논스 |
| 해시 함수 | 임의 데이터를 고정 길이 값으로. 조금만 바뀌어도 전혀 다른 값 |
| 머클 트리 | 거래들을 해시로 이진 트리 구성. 특정 거래 포함 여부를 효율적으로 증명 |
| 합의 알고리즘 | 누가 다음 블록을 만들지 정하는 규칙 |
| 노드 | 장부 사본을 보유하고 검증하는 참여자 |

**합의 알고리즘**

| 방식 | 원리 | 특징 |
|------|------|------|
| 작업증명(PoW) | 계산 문제를 먼저 푼 사람이 블록 생성 | 안전하지만 에너지 소모가 큼 |
| 지분증명(PoS) | 보유 자산에 비례해 블록 생성 권한 | 에너지 효율. 이더리움이 2022년 전환 |

**블록체인의 트릴레마**

탈중앙화·보안·확장성 셋을 동시에 만족하기 어렵다는 문제다. 이 제약이 다음 절들(가스비, 분산 스토리지)의 배경이다.

**면접 포인트**

블록체인 논문 두 편에 대해 **최소한의 기초는 답할 수 있어야 한다.** 다만 이 영역에서 깊이 있는 질문이 나올 가능성은 낮다. 면접관도 대개 이 분야 전문가가 아니고, 관심은 "왜 이 논문에 참여했는가"에 있다. 기초 개념을 정확히 말하되 모르는 부분은 솔직히 인정하는 편이 낫다.

### 스마트 컨트랙트와 토큰 표준

**직관**

블록체인 위에서 자동으로 실행되는 프로그램이다. "조건이 충족되면 자동으로 송금"처럼 중개자 없이 계약을 집행한다. 한번 배포하면 코드를 고칠 수 없는 것이 원칙이라(불변성), 버그가 곧 치명적 손실이 된다.

**주요 토큰 표준 (이더리움)**

| 표준 | 용도 | 특징 |
|------|------|------|
| ERC-20 | 대체 가능 토큰 | 서로 구별되지 않음. 화폐처럼 |
| ERC-721 | 대체 불가 토큰(NFT) | 각 토큰이 고유. 소유권 이전 가능 |
| ERC-1155 | 복합 | 대체 가능·불가를 한 계약에서 |
| ERC-4973 | Account-bound token | 양도 불가 토큰 표준 제안 |
| ERC-5192 | Minimal Soulbound NFT | 잠금 상태를 표현하는 최소 인터페이스 |

**가스비**

이더리움에서 연산과 저장에 드는 비용이다. **저장이 특히 비싸다.** 온체인에 데이터를 직접 넣으면 비용이 급격히 커지는데, 이것이 NFT의 이미지 파일을 블록체인에 직접 저장하지 않고 외부에 두는 이유다.

**면접 포인트**

**저장 비용 문제가 T12 논문의 출발점**이다. 논문 제목이 "Economical and Efficient Decentralized File Storage Methods"인 이유가 여기 있다. 온체인 저장은 비싸고, 중앙 서버에 두면 탈중앙화 취지에 어긋난다. 그 사이의 절충을 찾는 것이 문제 설정이다.

---

### NFT와 SoulBound Token

**직관**

NFT는 소유권을 나타내는 고유한 토큰이다. 사고팔 수 있다. **SoulBound Token(SBT)** 은 여기서 양도 기능을 뺀 것이다. 한번 받으면 다른 사람에게 넘길 수 없다.

왜 양도 불가가 필요한가. 졸업장, 자격증, 근무 이력, 의료 기록 같은 것은 **그 사람에게 귀속된 사실**이지 거래 대상이 아니다. 학위를 사고팔 수 있다면 학위의 의미가 사라진다.

**정의**

특정 지갑 주소에 영구히 귀속되어 전송이 불가능한 토큰이다. 2022년 비탈릭 부테린 등이 "탈중앙 사회(Decentralized Society)" 논문에서 개념을 제시했다.

**활용 시나리오**

| 분야 | 예 |
|------|-----|
| 학력·자격 | 학위, 수료증, 자격증 |
| 근무 이력 | 재직 증명, 경력 인증 |
| 의료 | 예방접종 기록, 진료 이력 |
| 평판 | 커뮤니티 기여, 신용 |
| 신원 | 탈중앙 신원(DID)의 구성요소 |

**핵심 난제**

| 문제 | 내용 |
|------|------|
| **키 분실** | 지갑 키를 잃으면 SBT를 영원히 되찾을 수 없다. 양도가 불가능하므로 새 지갑으로 옮길 수도 없다 |
| 프라이버시 | 온체인 데이터는 공개된다. 의료 기록 같은 것을 어떻게 다룰 것인가 |
| 발급자 신뢰 | 누가 발급했는지가 토큰의 가치를 결정 |
| 취소·갱신 | 자격이 취소되면 어떻게 반영할 것인가 |

**면접 포인트**

**키 분실 문제가 T13 논문의 주제다.** 논문 제목의 "Recovery Mechanism"과 "Guardian System"이 이를 가리킨다. SBT의 근본 딜레마를 한 문장으로 말할 수 있어야 한다: **"양도 불가능성이 SBT의 존재 이유인데, 바로 그 성질 때문에 키를 잃으면 복구할 수단이 없다."**

### 분산 파일 저장 (IPFS·아르위브)

**직관**

블록체인에 큰 파일을 직접 넣으면 비용이 감당이 안 된다. 그렇다고 중앙 서버에 두면 그 서버가 사라질 때 NFT가 가리키는 이미지도 사라진다. 분산 파일 저장은 파일을 여러 노드에 나눠 보관하고, 블록체인에는 그 파일을 가리키는 **주소만** 기록한다.

**IPFS (InterPlanetary File System)**

내용 기반 주소 지정(content addressing)을 쓴다. 파일의 해시가 곧 주소(CID)다.

| 성질 | 의미 |
|------|------|
| 내용 주소 | 파일 내용이 바뀌면 주소도 바뀐다 → 위변조 검증이 자동 |
| 중복 제거 | 같은 파일은 같은 주소 |
| **영속성 없음** | **아무도 보관하지 않으면 사라진다** |
| 피닝(pinning) | 특정 노드가 계속 보관하도록 고정. 유료 서비스(Pinata, Infura) 존재 |

**아르위브(Arweave)**

한 번 지불하면 영구 저장을 표방한다. 저장 비용을 기금화해 장기 보관 인센티브를 만드는 구조다.

**비교**

| 항목 | 온체인 | IPFS | 아르위브 | 중앙 서버 |
|------|--------|------|----------|-----------|
| 비용 | 매우 높음 | 낮음 | 중간(일회성) | 낮음(지속 과금) |
| 영속성 | 최고 | **보장 없음** | 높음 | 운영자에 의존 |
| 탈중앙화 | 최고 | 높음 | 높음 | 없음 |
| 검증 가능성 | 최고 | 해시로 검증 | 해시로 검증 | 없음 |

**면접 포인트**

**"IPFS에 올리면 영원히 남는 것 아닌가"** 는 흔한 오해다. IPFS는 **분산 저장 프로토콜이지 영속성 보장 시스템이 아니다.** 아무도 그 파일을 보관(pin)하지 않으면 사라진다. 이 점을 정확히 아는 것이 T12 논문의 "economical and efficient"라는 표현을 평가하는 기준이 된다. 비용을 낮추면서 영속성을 어떻게 확보했는지가 논문의 핵심일 것이므로 원문에서 확인해야 한다.

### 키 분실과 소셜 리커버리

**직관**

암호화폐 지갑은 개인키가 전부다. 잃으면 끝이다. 은행처럼 신분증을 들고 가서 재발급받을 수 없다. 소셜 리커버리는 **믿을 만한 사람들(가디언)에게 복구 권한을 나눠 주는** 방식이다. 그중 일정 수 이상이 동의하면 새 키로 계정을 옮길 수 있다.

**방식**

| 방식 | 원리 |
|------|------|
| 다중서명(Multisig) | N명 중 M명의 서명이 있어야 실행 |
| 샤미르 비밀 분산 | 비밀을 N조각으로 나누고 M조각이면 복원 |
| 소셜 리커버리 지갑 | 가디언들이 투표로 키 교체를 승인 |
| 계정 추상화(ERC-4337) | 지갑 자체를 스마트 컨트랙트로 만들어 복구 로직을 프로그래밍 |

**샤미르 비밀 분산의 원리**

`M-1`차 다항식을 만들고 비밀을 상수항에 둔다. 서로 다른 N개 점을 나눠 주면, M개 점이 모여야 다항식이 유일하게 결정되어 상수항(비밀)을 복원할 수 있다. M−1개로는 아무 정보도 얻지 못한다.

**새로 생기는 위험**

| 위험 | 내용 |
|------|------|
| 가디언 담합 | M명이 모의하면 계정을 탈취할 수 있다 |
| 가디언 상실 | 가디언들이 연락 두절·사망하면 복구 불가 |
| 사회공학 | 가디언을 속여 승인을 받아 낼 수 있다 |
| 프라이버시 | 가디언이 누구인지가 노출되면 표적이 된다 |

**고객 중심(customer-centric)이라는 설계 원칙**

T13 논문 제목에 나오는 표현이다. 일반 사용자는 개인키 관리에 익숙하지 않고, 가디언을 직접 지정하고 관리하는 것도 부담이다. 기술적으로 가능한 복구와 실제로 사용자가 쓸 수 있는 복구는 다르다. 사용성을 설계의 중심에 둔다는 뜻으로 읽힌다.

**면접 포인트**

**보안과 사용성의 트레이드오프**로 정리하면 답변이 깔끔하다. 복구를 쉽게 만들수록 공격 경로도 넓어진다. 가디언 수 M을 낮추면 복구가 쉽지만 담합 위험이 커지고, 높이면 안전하지만 실제로 복구가 안 될 수 있다. 이 균형점을 어디에 두느냐가 설계의 핵심이라고 답한다.

### LLM 기초와 트랜스포머 디코더

**직관**

거대 언어모델은 "다음 단어를 맞히는" 훈련만으로 만들어진다. 인터넷 규모의 텍스트에서 다음 토큰을 예측하도록 학습하면, 그 과정에서 문법·상식·추론 능력이 부수적으로 생긴다.

**구조**

GPT 계열은 트랜스포머의 **디코더만** 쓴다. 핵심은 **인과적 마스킹(causal masking)** 이다. 각 위치에서 앞쪽 토큰만 볼 수 있게 어텐션을 가려, 미래를 보고 답하는 부정행위를 막는다.

```
입력 토큰 → 임베딩 + 위치 인코딩
         → [마스크드 셀프 어텐션 → 피드포워드] × N층
         → 다음 토큰의 확률 분포
```

**학습 단계**

| 단계 | 내용 |
|------|------|
| 사전학습(Pre-training) | 대규모 텍스트에서 다음 토큰 예측 |
| 지시 조정(Instruction Tuning) | 지시-응답 쌍으로 미세조정 |
| 선호 정렬(RLHF / DPO) | 사람의 선호에 맞게 조정 |

**생성 파라미터**

| 파라미터 | 역할 |
|----------|------|
| temperature | 확률 분포의 날카로움. 낮으면 결정적, 높으면 다양 |
| top-k | 상위 k개 토큰 중에서만 샘플링 |
| top-p (nucleus) | 누적 확률 p까지의 토큰 중에서 샘플링 |
| max tokens | 최대 생성 길이 |

**Llama 계열**

Meta가 공개한 오픈 웨이트 모델군이다. Llama3-Instruct는 지시 조정까지 마친 버전으로, 프롬프트에 담긴 지시를 따르도록 훈련돼 있다.

**면접 포인트**

**"왜 오픈 모델(Llama)을 썼는가"** 라는 질문이 T02에서 나올 수 있다. 답의 요소: 로컬에서 돌릴 수 있어 API 비용과 데이터 유출 우려가 없고, 파인튜닝이 가능하며, 재현 가능한 연구를 위해 버전이 고정된 모델이 필요하다. 상용 API는 모델이 조용히 바뀌면 결과를 재현할 수 없다.

**환각(hallucination)** 문제도 짚을 수 있어야 한다. LLM은 그럴듯하지만 사실이 아닌 내용을 생성한다. T02처럼 LLM 출력을 다음 단계 입력으로 쓰는 파이프라인에서는 이 오류가 그대로 전파된다.

---

### 프롬프팅과 Chain-of-Thought

**직관**

같은 모델이라도 어떻게 묻느냐에 따라 답이 크게 달라진다. 특히 **"단계별로 생각해 보라"고 시키면 추론 문제의 정답률이 크게 오른다.** 이것이 Chain-of-Thought(CoT)다.

이유는 직관적이다. 모델이 최종 답을 바로 내려면 모든 계산을 한 번의 순전파에 압축해야 한다. 중간 과정을 글로 쓰게 하면, 그 글이 다음 단계의 입력이 되어 사실상 계산 공간이 넓어진다.

**주요 프롬프팅 기법**

| 기법 | 방법 |
|------|------|
| Zero-shot | 예시 없이 지시만 |
| Few-shot | 예시 몇 개를 함께 제시 |
| Chain-of-Thought | 중간 추론 과정을 쓰게 함 |
| Zero-shot CoT | "단계별로 생각해 봅시다"라는 문구만 추가 |
| Self-Consistency | 여러 번 생성해 다수결 |
| ReAct | 추론과 도구 사용(행동)을 번갈아 |

**구조화된 출력**

T02처럼 LLM 출력을 다음 단계가 소비해야 하는 파이프라인에서는 **출력 형식을 고정하는 것이 중요하다.** JSON 스키마를 지정하거나, 속성별로 항목을 나열하게 하거나, 예시를 제공해 형식을 학습시킨다. 자유 형식 텍스트가 나오면 파싱이 깨진다.

**면접 포인트**

**"CoT를 왜 썼는가"** 에 대한 답은 T02의 맥락에서 나와야 한다. 짧은 사용자 입력("흰 셔츠")을 상세한 속성 명세로 확장할 때, 그냥 확장하면 임의적이고 일관성이 없다. 단계를 나눠 생각하게 하면(어떤 소재인가 → 카라 형태는 → 후면은 전면과 어떻게 대응하는가) 속성이 체계적으로 채워지고 전면·후면 간 대응도 명시적으로 다뤄진다. 이 논리를 설명할 수 있어야 한다.

### Instruction Tuning

**직관**

사전학습만 마친 모델은 "다음 단어 맞히기 기계"라서, 질문을 하면 답하는 대신 비슷한 질문을 계속 이어 쓰기도 한다. 지시를 따르는 법을 따로 가르쳐야 한다. **지시-응답 쌍 데이터로 미세조정**하는 것이 instruction tuning이다.

**정의**

다양한 과제를 자연어 지시 형태로 변환한 데이터셋으로 지도 미세조정(SFT)을 수행한다.

```
데이터 형식:
  지시: "다음 문장을 영어로 번역하세요: 안녕하세요"
  응답: "Hello"
```

**효과**

- 지시를 따르는 능력이 생긴다
- **학습에 없던 과제에도 일반화된다** (zero-shot 성능 향상)
- 출력 형식을 제어하기 쉬워진다

**관련 개념**

| 용어 | 의미 |
|------|------|
| SFT (Supervised Fine-Tuning) | 지시-응답 쌍으로 미세조정. instruction tuning의 구현 |
| RLHF | 사람의 선호 순위로 보상모델을 학습하고 강화학습으로 정렬 |
| DPO | 보상모델 없이 선호 쌍으로 직접 최적화. RLHF보다 간단 |
| PEFT | LoRA 등 파라미터 효율적 미세조정. 전체 파인튜닝 대신 |

**면접 포인트**

**"instruction tuning을 직접 하셨는가, 이미 조정된 모델을 쓰셨는가"** 를 구분해 답해야 한다. Llama3-**Instruct**는 이름 그대로 이미 지시 조정이 완료된 모델이다. 이걸 그대로 썼다면 "instruction tuning된 모델을 활용했다"이고, 추가로 도메인 데이터로 조정했다면 "직접 수행했다"이다. 논문 원문에서 이 부분을 정확히 확인해야 한다. 애매하게 답하면 곤란해진다.

**답변:** 교신저자로 참여한 의류 이미지 생성 논문에서 활용했습니다. 사용자의 짧은 입력을 상세한 속성 명세로 확장하는 단계에 Llama3-Instruct를 썼고, Chain-of-Thought와 지시 조정을 결합한 방식입니다. 모델 자체를 처음부터 학습시킨 것은 아니고, 이미 지시 조정이 된 오픈 모델을 파이프라인의 한 구성요소로 활용했습니다. 오픈 모델을 쓴 이유는 로컬에서 실행할 수 있어 비용과 데이터 유출 우려가 없고, 상용 API처럼 모델이 조용히 바뀌어 결과 재현이 안 되는 문제를 피할 수 있어서였습니다.

**꼬리질문:** 파인튜닝은 직접 하셨습니까?

#### Q014. Chain-of-Thought가 왜 효과가 있습니까? 🟡

**의도:** 기법을 관행으로 쓰는지 원리를 아는지 본다.

**답변:** 모델이 최종 답을 바로 내려면 필요한 계산을 한 번의 순전파 안에 압축해야 합니다. 중간 과정을 글로 쓰게 하면 그 글이 다시 입력이 되어, 사실상 여러 번의 순전파를 이어 붙이는 셈이 됩니다. 계산할 공간이 넓어지는 것입니다. 저희 논문에서는 짧은 입력을 상세 명세로 확장할 때 썼는데, 그냥 확장하라고 하면 결과가 임의적이고 매번 달라집니다. 소재는 무엇인지, 카라 형태는 어떤지, 후면은 전면과 어떻게 대응하는지를 단계로 나눠 생각하게 하면 속성이 체계적으로 채워지고 전면과 후면의 대응도 명시적으로 다뤄집니다.

**꼬리질문:** LLM이 만든 설명이 사실과 다르면 이미지도 잘못 나오는 것 아닙니까?

#### Q015. Instruction Tuning이 무엇입니까? 🟡

**의도:** 논문 초록의 용어를 정확히 이해하는지 확인한다.

**답변:** 사전학습만 마친 언어모델은 다음 단어를 예측하는 기계라서, 질문을 하면 답하는 대신 비슷한 질문을 계속 이어 쓰기도 합니다. 지시를 따르는 법을 따로 가르쳐야 하는데, 다양한 과제를 지시와 응답 쌍의 형태로 만든 데이터로 미세조정하는 것이 instruction tuning입니다. 이렇게 하면 지시를 따르는 능력이 생기고, 학습에 없던 과제에도 일반화되며, 출력 형식을 제어하기 쉬워집니다. Llama3-Instruct는 이름 그대로 이 조정이 이미 완료된 모델입니다.

**꼬리질문:** 그럼 논문에서 말한 instruction tuning은 직접 수행한 겁니까, 조정된 모델을 쓴 겁니까?

#### Q016. 시계열 데이터를 다룰 때 교차검증을 어떻게 하십니까? 🟡

**의도:** 데이터 누수를 이해하는지 확인한다. P2와 T11 모두에 걸린다.

**답변:** 무작위 분할을 쓰면 안 됩니다. 미래 시점의 데이터로 학습해 과거를 예측하는 상황이 생겨서 성능이 실제보다 훨씬 좋게 나옵니다. 시간 순으로 분할하는 워크포워드 방식을 씁니다. 앞 구간으로 학습하고 바로 뒤 구간으로 검증한 다음, 학습 구간을 늘려 가며 반복합니다. 이렇게 하면 여러 시점에서의 성능을 얻을 수 있어서 시간에 따른 안정성도 볼 수 있습니다. 그리고 전처리에서도 주의해야 하는데, 표준화 같은 것을 전체 데이터로 먼저 하면 미래의 통계량이 과거 학습에 들어갑니다. 학습 구간의 통계량으로만 변환해야 합니다.

**꼬리질문:** 가스배관 프로젝트에서는 어떤 단위로 나누셨습니까?
