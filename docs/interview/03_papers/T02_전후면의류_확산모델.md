# T02 — 전후면 일관성을 갖는 의류 이미지 생성을 위한 2단계 확산 파이프라인

> **A Two-Stage Diffusion Pipeline for Consistent Front-Back Clothing Generation**
> Quantitative Bio-Science, Vol. 44, No. 1, pp. 9–31 (2025) · **교신저자**

---

## 0. 30초 요약

> 가상 피팅(VTON) 기술을 학습시키려면 같은 옷의 앞면과 뒷면 이미지가 짝으로 필요한데, 그런 데이터가 절대적으로 부족합니다. 이 연구는 사용자가 "하늘색 셔츠" 같은 짧은 문장 하나만 입력하면 앞면과 뒷면 이미지 한 쌍을 자동으로 만들어 주는 파이프라인을 제안했습니다. 핵심은 두 단계입니다. 먼저 Llama3-Instruct에 Chain-of-Thought를 적용해 짧은 입력을 색·소재·디자인이 명시된 상세 프롬프트 두 개로 확장하되, 앞면과 뒷면의 속성이 논리적으로 이어지도록 만듭니다. 그다음 FLUX로 앞면을 생성하고, SDXL에 IP-Adapter를 붙여 **앞면 이미지 자체를 참조하면서** 뒷면을 생성합니다. 텍스트만이 아니라 이미지까지 조건으로 넘기는 것이 일관성의 핵심입니다. 14개 품목으로 평가한 결과 성공 사례는 LPIPS 0.11~0.18, FID 35~50 수준이었고, 실패 사례에서 LLM이 앞면 전용 표현을 뒷면 프롬프트에 잘못 넣어 앞면이 두 번 생성되는 문제도 확인했습니다.

## 2. 왜 이 연구를 했나

### VTON 데이터의 구조적 부족

가상 피팅(Virtual Try-On, VTON)은 사용자 사진에 원하는 옷을 자연스럽게 합성하는 기술이다. 논문은 POVNet을 최신 VTON 모델의 예로 들며, 정밀한 워핑과 부분 생성으로 옷의 질감을 보존해 주름과 음영까지 사실적으로 재현한다고 소개한다.

문제는 **학습 데이터**다. 이런 모델을 학습시키려면 같은 옷의 여러 각도 이미지가 필요한데, 실제로 확보하려면:

- 옷 하나마다 앞뒤로 촬영해야 한다
- 촬영 조건(조명·배경·거리)을 통일해야 한다
- 품목 수만큼 이 과정을 반복해야 한다

**촬영 비용이 데이터 규모의 상한**이 된다.

### 기존 연구가 다루지 않은 지점

논문은 선행 연구를 이렇게 정리한다.

| 선행 연구 방향 | 한계 |
|----------------|------|
| 프롬프트 구조와 하이퍼파라미터가 생성에 미치는 영향 분석 [9] | 단일 이미지 생성에 머묾 |
| 자동 추천 시스템으로 사용자 탐색을 돕기 [10] | 데이터셋 구축이 목표가 아님 |

즉 기존 연구는 **텍스트를 이미지로 바꾸는 변환과 최적화**에 초점이 있었다. 이 논문이 겨냥한 빈칸은 **"논리적 추론을 포함해 일관성 있는 데이터셋을 구축하는 것"** 이다.

논문 서론의 표현을 그대로 옮기면, 기존 접근은 사용자 입력을 단순 변환하거나 매칭하는 데 그쳤으나, 이 연구는 **CoT로 논리적 중간 추론 과정을 거쳐 정제된 프롬프트를 만들고**, 여기에 Instruction Tuning을 결합해 기존보다 훨씬 풍부한 정보를 담은 프롬프트를 생성한다.

### 두 기술 흐름의 수렴

논문은 최근 AI 연구의 두 흐름을 짚고 이 연구를 그 교차점에 놓는다.

```
흐름 1: 이미지 생성 기술의 발전 (VAE → GAN → Diffusion → VTON)
흐름 2: CoT와 Instruction Tuning 기반 추론·적응 능력의 향상
                      ↓
          두 흐름의 결합 = 이 연구의 자리
```

### 실질적 목표

**"짧은 사용자 입력 하나로 앞뒤가 일관된 고품질 의류 이미지 쌍을 만들어 데이터셋 부족 문제를 푼다."**

## 3. 사전지식 (A to Z)

### 3.1 확산모델

노이즈를 조금씩 더해 이미지를 완전한 잡음으로 만드는 순방향 과정과, 그 역을 학습해 잡음에서 이미지를 복원하는 역방향 과정으로 이뤄진다. 학습은 "이 이미지에 섞인 노이즈가 무엇인가"를 맞히는 회귀 문제라 GAN보다 안정적이다.

논문 관련연구도 같은 구도로 설명한다. VAE는 잠재 구조를 잘 잡지만 결과가 흐릿하고, GAN은 선명하지만 학습이 불안정하며, 확산모델이 두 계보의 아이디어를 통합한 새 패러다임이라는 서술이다.

→ 상세: [05_생성모델_GAN·Diffusion.md](../01_foundations/05_생성모델_GAN·Diffusion.md)의 `### 확산모델의 직관`, `### DDPM의 순방향과 역방향 과정`

### 3.2 SDXL

Stable Diffusion XL. 잠재 확산모델의 고해상도 버전이다. 텍스트로부터 이미지를 만드는 능력이 강하고, 생태계가 성숙해 **IP-Adapter 같은 조건 제어 모듈이 잘 지원된다.**

### 3.3 FLUX

Black Forest Labs가 공개한 확산 트랜스포머 기반 모델이다. 논문은 FLUX를 고른 이유로 **"기존 Stable Diffusion 계열 모델보다 세부를 풍부하게 보존하고 입력 프롬프트를 더 강하게 따른다"** 는 점을 든다. 프롬프트 준수도가 높다는 것은 CoT로 만든 상세 서술이 실제로 이미지에 반영되는지 검증하기에 유리하다는 뜻이다.

### 3.4 IP-Adapter — 이 논문의 기술적 열쇠

**Image Prompt Adapter.** 텍스트뿐 아니라 **이미지를 조건으로** 확산모델에 넣을 수 있게 하는 모듈이다.

작동 방식은 이렇다. 참조 이미지를 이미지 인코더에 통과시켜 임베딩을 만들고, 그 임베딩을 확산 U-Net의 교차 어텐션에 **추가 경로로** 주입한다. 원본 모델의 텍스트 조건 경로는 그대로 두고 이미지 경로를 병렬로 더하는 구조라, 텍스트와 이미지를 동시에 조건으로 쓸 수 있다.

**이 논문에서의 역할**: 뒷면을 생성할 때 앞면 이미지를 참조하게 해서, 색과 질감이 앞뒤로 이어지게 만든다. 논문은 **IP-Adapter가 없으면 뒷면 프롬프트만으로 생성한 결과가 앞면과 전혀 무관할 수 있다**고 명시한다.

→ 상세: [05_생성모델_GAN·Diffusion.md](../01_foundations/05_생성모델_GAN·Diffusion.md)의 `### ControlNet` (같은 계열의 조건 주입 기법)

### 3.5 Instruction Tuning

사전학습만 마친 언어모델은 지시를 따르는 법을 모른다. 지시-응답 쌍 데이터로 미세조정해 지시 준수 능력을 부여하는 것이 instruction tuning이다. Llama3-**Instruct**는 이 과정이 완료된 모델이다.

→ 상세: [06_강화학습·시계열·기타.md](../01_foundations/06_강화학습·시계열·기타.md)의 `### Instruction Tuning`

### 3.6 Chain-of-Thought

모델에게 중간 추론 과정을 명시적으로 쓰게 하는 프롬프트 설계 기법이다. 논문의 설명을 요약하면, 일반적인 few-shot은 입력과 최종 답만 예시로 주는데 CoT는 **답에 이르는 논리적 사고 과정까지 예시에 포함**시켜, 모델이 답과 함께 문제 해결 절차를 배우게 한다.

→ 상세: [06_강화학습·시계열·기타.md](../01_foundations/06_강화학습·시계열·기타.md)의 `### 프롬프팅과 Chain-of-Thought`

### 3.7 평가지표

| 지표 | 재는 것 | 방향 |
|------|---------|------|
| LPIPS | 두 이미지의 지각적 유사도(신경망 특징 거리) | 낮을수록 유사 |
| FID | 생성 이미지 분포와 실제 분포의 거리 | 낮을수록 좋음 |
| Precision | 생성 결과가 프롬프트 요구를 얼마나 충실히 반영했는가 | 높을수록 좋음 |
| Recall | 다양한 시각적 특징을 얼마나 포착했는가 | 높을수록 좋음 |

## 4. 방법론 단계별 해부

### 4.1 전체 파이프라인 (논문 Fig. 1)

```
사용자 입력: "sky-blue shirt"  (짧은 한 줄)
        ↓
┌─────────────────────────────────────────────────┐
│ 1단계: LLM 프롬프트 확장 (Llama3-Instruct)        │
│                                                 │
│  [User Input] → [Instruction Tuning]            │
│      → [Front/Back 초안 서술]                    │
│      → [CoT 검증]                                │
│      → [최종 Front Prompt + Back Prompt]         │
└─────────────────────────────────────────────────┘
        ↓                          ↓
   Front Prompt               Back Prompt
        ↓                          ↓
┌──────────────────┐    ┌──────────────────────────┐
│ 2단계-A: FLUX     │    │ 2단계-B: SDXL + IP-Adapter│
│ 앞면 생성          │───→│ 앞면 이미지를 참조해 뒷면 생성│
│ 512 × 512        │    │ 512 × 512                │
└──────────────────┘    └──────────────────────────┘
        ↓                          ↓
    앞면 이미지                  뒷면 이미지
        └──────── 일관된 한 쌍 ────────┘
```

**전 과정이 자동화**되어, 사용자는 텍스트 한 줄만 넣으면 된다.

논문이 밝히는 파이프라인의 핵심은 **"텍스트 정보와 시각 정보를 모두 활용해 일관성을 극대화하는 것"** 이다. LLM이 만든 두 프롬프트가 같은 옷을 서술하되 두 시점의 차이를 반영하고, 확산 단계에서는 앞면 이미지에서 뽑은 시각 특징이 뒷면 생성에 재사용된다.

### 4.2 1단계: LLM 프롬프트 확장

**두 하위 단계로 나뉜다.**

**(a) Instruction Tuning 단계**

사용자가 입력한 한 줄을 앞면·뒷면 각각에 대한 상세 지시로 변환한다.

```
입력: "sky-blue shirt"
   ↓
Front Prompt 초안: "셔츠의 앞면 이미지를 생성하라"
Back Prompt 초안:  "같은 셔츠의 뒷면 이미지를 생성하라"
```

각 프롬프트에는 **색상(sky-blue), 소재(면 또는 실크), 디자인 세부(자수 패턴, 단추 배치, 밑단 형태)** 가 채워진다. 논문은 이 요소들이 **사전에 정의된 패션 속성 목록과 일반 지식을 바탕으로 자동 반영**되며, LLM이 자신의 대규모 지식으로 빈 곳을 메운다고 서술한다.

**(b) CoT 검증 단계**

논리적 일관성을 확보하는 단계다. LLM이 앞면 프롬프트에 언급된 디자인 요소들을 **체계적으로 검토해 뒷면 프롬프트로 이어지게** 한다.

논문이 든 예시가 이 단계를 가장 잘 보여 준다.

```
앞면 프롬프트: "앞여밈(front placket)을 따라 흰색 자수 패턴이 있다"
        ↓ CoT 검토
뒷면 프롬프트: "뒷목 요크(back yoke)를 따라 이에 대응하는 흰색 자수 패턴이 있다"
```

**단순 복사가 아니라 대응 관계를 만든다는 것이 핵심이다.** 앞여밈은 뒷면에 없는 부위이므로, 같은 자수를 뒷면의 대응 부위(요크)에 배치한다. 이 대응을 만들려면 옷의 구조에 대한 추론이 필요하고, 그것이 CoT를 쓰는 이유다.

**최종 흐름**

```
[User Input] → [instruction tuning] → [Front/Back 초안] → [CoT 검증] → [최종 Front/Back Prompt]
```

**중요 — 추가 파인튜닝은 하지 않았다**

논문은 **"프롬프트 설계를 통해 모델의 출력을 제어했으며, 추가적인 파인튜닝 없이(without additional fine-tuning)"** 수행했다고 명시한다. 즉 Llama3-Instruct를 그대로 쓰고 프롬프트만 설계했다. 이 점을 정확히 알아야 한다.

> ※ 배경 보충 — 논문 3.2절에는 "Llama3 기반의 파인튜닝된 InstructGPT 계열 모델을 사용했다"는 표현과 "추가 파인튜닝 없이"라는 표현이 함께 나온다. 앞 문장은 Llama3-Instruct가 **이미 지시 조정을 거친 모델**이라는 뜻으로, 뒤 문장은 **이 연구에서 별도로 조정하지 않았다**는 뜻으로 읽는 것이 정합적이다. 면접에서는 "이미 instruction tuning이 된 공개 모델을 프롬프트 설계만으로 활용했다"고 답하는 것이 정확하다.

**오픈소스 모델을 쓴 이유**: 논문은 **재현 용이성(ease of reproducibility)** 을 명시적 근거로 든다.

### 4.3 2단계-A: 앞면 생성 (FLUX)

Front Prompt를 FLUX에 넣어 앞면 이미지를 만든다.

**FLUX를 고른 근거 (논문 3.3절)**

- 기존 Stable Diffusion 계열보다 **세부를 풍부하게 보존**한다
- **프롬프트를 강하게 따른다**. CoT로 만든 텍스트 서술이 이미지에 실제로 반영되는지 검증하는 데 특히 유용하다

**동작**: "은은한 광택이 있는 하늘색 실크 블라우스, 앞여밈을 따라 정교한 흰색 자수"라는 문장을 벡터 임베딩으로 바꾸고, 확산 트랜스포머 네트워크를 통해 단계별로 노이즈를 걷어 낸다. 각 단계에서 트랜스포머가 텍스트의 의미(색=하늘색, 소재=실크, 디테일=자수)를 해석해 이미지에 반영한다.

**출력**: 512 × 512 픽셀.

**샘플 선택**: FLUX가 여러 샘플을 만들면 **프롬프트에 가장 잘 맞는 것을 고른다.** 서술된 자수가 뚜렷하게 보이는 이미지 같은 기준이다. 이 앞면 이미지가 다음 단계의 시각 참조가 된다.

> 이 "샘플 선택"이 사람의 개입인지 자동인지는 원문에 명시되지 않음. 자동화를 주장하는 파이프라인에서 이 지점이 수동이라면 완전 자동은 아니게 되므로, 면접에서 물어보면 이렇게 답해야 한다.

### 4.4 2단계-B: 뒷면 생성 (SDXL + IP-Adapter)

Back Prompt를 SDXL에 넣되, **IP-Adapter로 앞면 이미지를 함께 조건으로 준다.**

```
Back Prompt (텍스트) ─────┐
                          ├──→ SDXL 확산 과정 ──→ 뒷면 이미지 (512×512)
앞면 이미지 → IP-Adapter ─┘
             (이미지 임베딩)
```

**이 조합을 고른 근거 (논문 3.2절 후반) — 가장 중요한 설계 판단**

논문은 왜 앞면과 뒷면에 **다른 모델**을 썼는지를 명확히 설명한다.

| 모델 | 강점 | 약점 |
|------|------|------|
| **SDXL** | 이미지 조건 부여 능력이 뛰어남 (IP-Adapter 지원) | **옷만 요청해도 사람 형상을 자주 포함시킨다** → 깨끗한 초기 참조 이미지를 만들기에 부적합 |
| **FLUX** | 텍스트로부터 **옷만 있는 이미지를 더 안정적으로** 생성. 프롬프트 준수도 높음 | 직접적인 이미지-투-이미지 조건 부여(IP-Adapter 등)에 대한 **공식 지원이 부족** |

**결론**: FLUX의 강점(깨끗한 앞면)을 쓰고, SDXL의 강점(우수한 이미지 조건 부여)을 써서 뒷면의 일관성과 디테일을 확보한다. 논문 표현으로는 **"목표 달성을 위한 가장 효과적인 경로"** 다.

**IP-Adapter가 실제로 하는 일**

앞면 이미지를 이미지 임베딩으로 변환해 SDXL의 확산 과정에 통합한다. SDXL은 Back Prompt(옷의 형태, 뒷면 고유 디테일 같은 텍스트 정보)와 앞면의 시각 정보(색상, 질감)를 **동시에** 고려해 뒷면을 합성한다.

논문이 든 예: 앞면에 특정 로고가 있으면 뒷면에도 적절히 배치된 같은 로고가 나타나고, 앞면의 질감이 뒷면에 반영된다.

**IP-Adapter가 없으면**: 논문은 **"Back Prompt만으로 생성한 뒷면은 앞면과 전혀 무관할 수 있다"** 고 명시한다. IP-Adapter가 있어야 앞면에 드러난 디자인 언어가 뒷면까지 확장된다.

**후처리**: 필요하면 가벼운 업스케일링과 노이즈 제거를 적용해 최종 이미지를 만든다.

### 4.5 설계의 논리를 한 줄로

**텍스트 일관성(LLM/CoT) + 시각 일관성(IP-Adapter) = 두 겹의 일관성 장치.**

프롬프트 수준에서 속성을 맞추고, 이미지 수준에서 시각 특징을 이어받는다. 어느 한쪽만으로는 부족하다는 것이 이 파이프라인의 전제다.

## 5. 핵심 수식

이 논문은 방법론 제안 논문이라 새로 유도한 수식이 없다. 관련연구에서 확산모델의 표준 정식화를 인용한다.

**순방향 과정**

```
q(x_t | x_{t-1}) = N( x_t ; √(1 − β_t) · x_{t-1} , β_t I )
```

- `x_t`: t단계까지 노이즈가 더해진 이미지
- `β_t`: t단계의 노이즈 크기
- `N(·; μ, Σ)`: 평균 μ, 공분산 Σ의 정규분포
- 각 단계의 출력이 **직전 출력에만 의존**한다 → 마르코프 성질

**역방향 과정**

```
p_θ(x_{t-1} | x_t) = N( x_{t-1} ; μ_θ(x_t, t) , Σ_θ(x_t, t) )
```

- `μ_θ(x_t, t)`: 예측된 평균
- `Σ_θ(x_t, t)`: 노이즈 제거 정도. 구현에 따라 공분산 행렬로 표현

**학습 목표**

```
L(θ) = E_{t, x_0, ε} [ ‖ ε − ε_θ(x_t, t) ‖² ]
```

- `ε`: 실제로 더한 노이즈
- `ε_θ(x_t, t)`: 모델이 예측한 노이즈
- 각 단계에서 정확한 노이즈 제거를 수행하도록 모델을 유도한다

**읽는 법**: 이것은 **MSE 회귀**다. 정답(더한 노이즈)이 있는 지도학습이라 GAN처럼 판별기와의 균형을 맞출 필요가 없고, 그래서 학습이 안정적이다.

**평가지표 — LPIPS**

```
LPIPS(x, y) = Σ_l  w_l ⊙ ‖ φ_l(x) − φ_l(y) ‖²  (층별 가중 거리의 합)
```

- `φ_l`: 사전학습 신경망의 l번째 층 특징
- `w_l`: 층별 학습된 가중치
- MSE 같은 픽셀 단위 차이가 아니라 **신경망 중간층 특징 사이의 거리**를 재므로 사람의 지각과 더 잘 맞는다

**평가지표 — FID**

```
FID = ‖ μ_r − μ_g ‖² + Tr( Σ_r + Σ_g − 2(Σ_r Σ_g)^(1/2) )
```

- `μ_r, Σ_r`: 실제 이미지 특징의 평균·공분산 (Inception v3로 추출)
- `μ_g, Σ_g`: 생성 이미지 쪽

### 7.3 실패 사례 분석 — 이 논문에서 가장 값진 부분

논문이 실패를 숨기지 않고 원인까지 분석한 것은 평가할 만하다.

**(a) Jeans (LPIPS 0.25, FID 90) / Blue hoodie (0.22, 85)**

원인: **의도하지 않은 요소가 들어갔다.** 모델(사람)과 배경이 이미지에 포함됐다.

이것이 지표를 두 방향으로 악화시켰다.

- **LPIPS 악화**: 옷 이외의 요소가 순수한 옷 대 옷 일관성 평가를 방해했다. 옷 자체의 색과 주요 패턴은 앞뒤로 어느 정도 일관성을 유지했음에도 점수가 나빴다
- **FID 악화**: "옷만 있는" 이미지 분포와의 유사성이 떨어졌다
- **Precision 하락** (0.65, 0.68): 목표한 "옷만" 특성을 정확히 표현하지 못했다

**이 실패가 4.4절의 설계 근거를 뒷받침한다.** SDXL이 옷만 요청해도 사람을 넣는 경향이 있다고 했는데, 뒷면 생성에는 SDXL을 쓰므로 그 경향이 남아 있는 것이다.

**(b) Mint windbreaker (LPIPS 0.90, FID 180) — 가장 주목할 실패**

현상: **뒷면을 요청했는데 앞면이 생성됐다.**

원인 (논문 부록 B.3): **LLM 프롬프트 생성 단계의 결함.** 앞면 고유 특징인 **"zip-up closure(지퍼 여밈)"** 가 뒷면 프롬프트에 잘못 포함됐다. 지퍼는 앞면에만 있는 요소인데 뒷면 서술에 들어가자, 이미지 생성 모델이 앞면을 다시 만들도록 유도된 것이다.

**이 실패가 말해 주는 것**

```
LLM 프롬프트 오류  →  이미지 생성 오류  →  파이프라인 전체 실패
```

**단계형 파이프라인의 구조적 취약성**이다. 앞 단계의 오류가 걸러지지 않고 뒤로 전파된다. CoT가 일관성을 만들도록 설계됐지만, 그 CoT 자체가 틀리면 막을 장치가 없다.

### 7.4 논문의 결론

- CoT와 Instruction Tuning을 적용해 앞뒤가 일관된 의류 이미지를 생성하는 방법론을 제안했다
- **단순한 텍스트 입력만으로** 고품질 이미지 쌍을 얻을 수 있음을 보였다
- 추가 촬영이나 복잡한 3D 모델링 없이 다각도 이미지를 확보할 수 있다는 점이 패션 데이터셋 구축의 새로운 패러다임을 시사한다
- 정량 평가는 성공 사례에서 방법론의 효과를, 실패 사례에서 개선 지점을 보여 준다

### 7.5 논문이 밝힌 한계 (5·6장)

| 한계 | 내용 |
|------|------|
| 1. 배경 제약 | **단색 배경 위의 옷만** 생성한다. 사람이 실제로 입은 이미지나 복잡한 배경에는 직접 적용하기 어렵다 |
| 2. 각도 제약 | **앞뒤 두 각도만** 다뤘다. 측면이나 45도 같은 중간 각도는 미해결 |
| 3. LLM 의존 | 프롬프트 확장이 전적으로 LLM에 의존해, LLM이 옷에 대해 잘못된 가정을 하면 의도치 않은 디테일이 나타난다. 뒷면을 요청했는데 앞면이 생성된 사례가 그 예 |
| 4. 속도 | FLUX와 SDXL 같은 대형 생성모델은 **이미지 한 장에 수 초**가 걸린다. 대량 생산 시 시간이 많이 든다 |

### 7.6 논문이 제시한 향후 방향

- **다양한 인체 실루엣과 자세로 확장**: 사람이 실제로 옷을 입은 앞뒤(및 다른 각도) 이미지 생성. 정면 사진 한 장과 옷 종류만 주면 뒷면을 생성하는 형태가 되면 VTON에 더 현실적으로 기여
- **효율화와 경량화**: 실시간 반응성 확보. 인터랙티브 패션 디자인 도구나 실시간 온라인 피팅 서비스를 겨냥
- **윤리적 고려**: 저작권 문제, 데이터 오용 방지, 실재하지 않는 옷 이미지로 인한 소비자 혼란 방지. AI 생성 패션 이미지의 윤리적 활용 가이드라인 제안 계획

## 8. 한계와 반박 대응

**교신저자 논문이므로 이 절이 특히 중요하다.** 방법론의 약점을 지적받았을 때 방어하는 것이 교신저자의 역할이다.

### 8.1 LPIPS를 일관성 지표로 쓴 것이 타당한가 — 가장 날카로운 지점

**문제 제기**: LPIPS는 두 이미지가 얼마나 **닮았는지**를 재는 지표다. 낮을수록 유사하다. 그런데 옷의 앞면과 뒷면은 **원래 달라야 한다.** 앞면에는 단추와 여밈이 있고 뒷면에는 없다. 완전히 같으면 그건 오히려 실패다.

극단적으로 말하면, **앞면 이미지를 그대로 복사해 뒷면이라고 내놓으면 LPIPS가 0이 되어 최고 점수를 받는다.**

**대응 논리**

1. 이 지표는 **절대 기준이 아니라 상대 비교용**이다. IP-Adapter 없이 독립 생성한 경우와 비교해 색·질감의 연속성이 개선됐는지를 보는 용도다
2. 실제로 실패 사례의 LPIPS(0.22~0.90)와 성공 사례(0.11~0.18)가 뚜렷이 갈리므로, 이 데이터 범위에서는 판별력이 있었다
3. 다만 **"낮을수록 좋다"가 무한정 성립하지 않는다**는 점은 논문이 명시했어야 한다. 적정 범위가 있는 지표다

**더 나은 지표라면**: 옷의 속성별 일치도(색상 히스토그램 유사도, 질감 특징 거리)와 구조적 차이(뒷면 고유 요소의 존재)를 분리해 재야 한다. 또는 사람 평가자에게 "같은 옷으로 보이는가"를 묻는 방식이 목적에 더 부합한다.

**답변 전략**: 지적을 인정하고 위 대안을 제시한다. 지표 선택의 한계를 아는 것이 교신저자로서의 태도다.

### 8.2 FID를 품목 단위로 계산한 것

**문제 제기**: FID는 **두 이미지 집합의 분포 거리**를 재는 지표다. 논문 본문에는 "이 이미지의 FID는 40이었다"는 표현이 나오고, Table 1은 품목마다 FID 값을 하나씩 싣는다. 품목당 이미지가 앞뒤 2장뿐이라면, 그 표본으로 계산한 공분산 행렬은 의미가 없다.

FID는 통상 **1만 장 이상**을 요구하며, 표본이 적으면 값이 심하게 편향된다는 것이 잘 알려져 있다.

**대응 논리**

1. Table 1의 FID는 **품목 단위 상대 비교를 위한 참고값**으로 읽어야 하고, 절대 수치로 해석하면 안 된다
2. 실제로 성공군(35~50)과 실패군(85~180)의 차이가 크므로 순위 정보로서는 기능했다
3. 다만 **어떤 실제 이미지 집합과 비교했는지, 몇 장으로 계산했는지가 논문에 없다.** 이 부분은 명시했어야 한다

**답변 전략**: "FID를 품목 단위로 보고한 것은 방법론적으로 정확하지 않습니다. 전체 50개 품목의 생성 이미지를 하나의 집합으로 묶어 실제 의류 이미지 데이터셋과 비교하는 방식이 맞습니다. 이 부분은 개선이 필요하다고 봅니다."

### 8.3 기준선과의 정량 비교가 없다

**문제 제기**: 6.3절에서 기준선(짧은 프롬프트 + SDXL 단독, IP-Adapter 없음)을 설정한다고 했는데, **Table 1에는 제안 방법의 점수만 있다.** 기준선의 LPIPS·FID·Precision·Recall이 보고되지 않았다.

따라서 **"제안 방법이 기준선보다 낫다"는 정량적 근거가 논문에 없다.** 정성적 서술(IP-Adapter가 없으면 무관한 이미지가 나올 수 있다)만 있다.

**이것이 이 논문의 가장 명확한 방법론적 결함이다.**

**답변 전략**: 변명하지 말고 인정한다. "기준선의 정량 점수를 함께 실었어야 합니다. 비교 대상 없이 제안 방법의 절대 수치만 제시하면 개선 폭을 알 수 없습니다. 게재 후 이 부분을 가장 아쉽게 생각합니다."

### 8.4 표본이 작다

50개 프롬프트를 만들었다고 했으나 Table 1에는 14개만 실렸다. **나머지 36개를 왜 빼고 어떤 기준으로 골랐는지가 원문에 없다.** 성공 사례만 골라 실었다면 선택 편향이고, 실패 사례 3개를 실은 것을 보면 그렇지는 않아 보이지만 기준이 불명확하다.

**답변 전략**: "지면 제약으로 대표 사례를 실었을 것으로 이해하지만, 50개 전체의 지표 분포(평균, 표준편차, 성공률)를 요약해 제시했어야 합니다."

### 8.5 생성 데이터로 학습한 모델이 실제로 좋아지는지 검증하지 않았다

이 연구의 목적은 **VTON 학습용 데이터셋 구축**이다. 그렇다면 진짜 검증은 **"이 데이터로 VTON 모델을 학습시켰더니 성능이 올랐는가"** 여야 한다. 논문은 여기까지 가지 않았다.

이것이 합성 데이터 연구의 표준적 검증 방식(다운스트림 평가)이다.

**답변 전략**: "이 논문은 데이터 생성 파이프라인 제안까지이고, 그 데이터의 유용성을 다운스트림 과제로 검증하는 것이 다음 단계입니다. 실제로 VTON 모델을 이 데이터로 학습시켜 실제 데이터만 쓴 경우와 비교하는 실험이 필요하다고 봅니다."

→ 관련: [05_생성모델_GAN·Diffusion.md](../01_foundations/05_생성모델_GAN·Diffusion.md)의 `### 합성 데이터로 학습하기`

### 8.6 단계형 파이프라인의 오류 전파

Mint windbreaker 사례가 보여 준 대로, LLM 단계의 오류가 검증 없이 이미지 단계로 넘어간다.

**개선 방향을 말할 수 있어야 한다.**

- **규칙 기반 검증층**: 앞면 전용 속성(zip-up closure, front placket, buttons) 목록을 만들어 뒷면 프롬프트에서 걸러낸다
- **생성 후 검증**: 만들어진 뒷면 이미지를 분류기나 VLM으로 검사해 "뒷면이 맞는가"를 판정하고, 아니면 재생성한다
- **자기 일관성**: LLM에게 여러 번 프롬프트를 만들게 하고 일치하는 것만 채택한다

### 8.7 LLM의 환각

프롬프트 확장이 LLM의 일반 지식에 의존하므로, 실재하지 않거나 물리적으로 불가능한 옷의 속성이 들어갈 수 있다. 논문도 한계 3번으로 인정했다. 생성된 옷이 실제 제품과 다른 구조를 가지면, 그 데이터로 학습한 VTON 모델이 잘못된 사전 지식을 갖게 된다.

### 8.8 저작권과 윤리

논문이 향후 과제로 스스로 제기한 부분이다. 확산모델은 저작권 있는 이미지로 학습됐을 가능성이 있고, 생성 결과가 특정 브랜드 디자인과 유사할 수 있다. 실재하지 않는 옷의 이미지가 상거래에 쓰이면 소비자 혼란도 생긴다. **교신저자로서 이 문제를 인식하고 있다는 것을 보여 주는 것이 좋다.**

#### Q016. 지금 이 연구를 다시 한다면 무엇을 바꾸시겠습니까? 🟡

**의도:** 자기 연구를 비판적으로 볼 수 있는지, 개선안이 구체적인지 본다.

**답변:** 평가 설계를 가장 먼저 바꾸겠습니다. 기준선의 정량 점수를 반드시 함께 싣고, FID는 품목 단위가 아니라 전체 생성 집합과 실제 의류 데이터셋 사이에서 계산하겠습니다. 일관성 지표도 LPIPS 하나가 아니라 색상 일치도와 뒷면 고유 요소의 존재 여부를 분리해서 보고, 사람 평가를 병행하겠습니다. 파이프라인 쪽에서는 LLM 출력에 대한 검증층을 넣겠습니다. 앞면 전용 속성이 뒷면 프롬프트에 들어가지 않도록 걸러내는 규칙과, 생성된 이미지가 정말 뒷면인지 확인하는 사후 검증입니다. 그리고 궁극적으로는 생성한 데이터로 VTON 모델을 학습시켜 성능이 실제로 오르는지 확인하는 데까지 가야 이 연구의 목적이 검증된다고 봅니다.

**꼬리질문:** 그중에 가장 먼저 하시겠습니까?

#### Q017. 확산모델로 만든 옷 이미지에 저작권 문제는 없습니까? 🔴

**의도:** 윤리적 인식을 본다. 논문이 스스로 제기한 문제이므로 답할 수 있어야 한다.

**답변:** 논문 마지막에 향후 과제로 명시한 부분입니다. 두 층위의 문제가 있다고 봅니다. 하나는 학습 데이터입니다. FLUX나 SDXL 같은 모델이 저작권 있는 이미지로 학습됐을 가능성이 있고, 그 결과 생성물이 특정 브랜드의 디자인과 유사해질 수 있습니다. 다른 하나는 활용 층위인데, 실재하지 않는 옷의 이미지가 상거래에 쓰이면 소비자가 실제 제품으로 오인할 수 있습니다. 특히 이 연구가 VTON 데이터를 목표로 하므로 실제 쇼핑 환경에 닿을 가능성이 있어 더 신경 써야 한다고 봅니다. 논문에서는 AI 생성 패션 이미지의 윤리적 활용 가이드라인을 제안하는 후속 연구를 계획한다고 밝혔습니다.

**꼬리질문:** 그런 가이드라인에 무엇이 들어가야 한다고 보십니까?
