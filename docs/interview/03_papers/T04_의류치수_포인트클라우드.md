# T04 — 컴퓨터 비전 딥러닝 모델과 포인트 클라우드를 이용한 의류 치수 자동 측정

> **Automatic Measurements of Garment Sizes Using Computer Vision Deep Learning Models and Point Cloud Data**
> Applied Sciences, 2022, 12(10), 5286 · 공저(4/6)

---

## 0. 30초 요약

> 옷의 치수를 재는 일은 판매자에게도 구매자에게도 비용입니다. 제조사는 품질 관리를 위해 반복 측정하고, 소비자는 사이즈가 예상과 달라 교환·반품을 합니다. 기존 자동 측정은 2D 이미지 기반이라 픽셀 거리를 실제 거리로 바꾸려면 카메라 거리·각도·조명판까지 전부 통제해야 했습니다. 저희는 LiDAR가 달린 태블릿으로 **한 번만 촬영해서** 치수를 재는 방법을 제안했습니다. HRNet-W48로 옷의 치수 측정점을 찾고, 그 점들을 포인트 클라우드에 매핑해 실제 거리를 계산합니다. 중고 의류 33벌을 두 가지 배경에서 660세트 촬영해 검증했더니 평균 상대오차가 1.59%와 2.08%였습니다. **사람이 직접 잰 값의 오차가 3.25%였으니 수동 측정보다 정확했습니다.** 배경판을 깔든 맨바닥이든 성능이 유지된 것이 이 방법의 실용적 가치입니다.

## 2. 왜 이 연구를 했나

### 산업의 실제 비용

논문 서론이 문제를 비용 관점으로 정리한다.

| 주체 | 비용 |
|------|------|
| 의류 제조사 | 품질 관리를 위해 **정기적으로 제품 치수를 반복 측정** |
| 소매점·중고 매장 | 소비자에게 사이즈 라벨과 정확한 치수를 제공하려고 **다시 측정** |
| 소비자 | 정보가 제공돼도 사이즈가 예상과 달라 **교환·반품** |

논문의 진단: 대량생산을 위해 만들어진 사이즈 표준이 폭넓은 소비자를 다 감당하기에 부적절하다. 이런 반복적이고 비효율적인 작업이 업계 전반에 퍼져 있어 결국 의류 시장의 비용을 크게 올린다.

### 기존 2D 방식의 한계 — 논문 Table 3의 근거

기존 방법은 2D 이미지에만 의존했기 때문에, 각 픽셀에 공간 정보를 매핑하려면 **정교한 환경 통제와 카메라 캘리브레이션**이 필요했다.

통제해야 할 것들:

- 옷과 카메라 사이의 거리
- 카메라 렌즈의 각도와 곡률
- 옷 아래의 조명판
- 배경판

**즉 장비 설치 공간과 준비 작업이 필요하다.** 소규모 사업자나 일반 소비자에게는 비현실적이다.

### 이 논문의 해법

**LiDAR가 각 지점까지의 거리를 직접 기록하므로 캘리브레이션이 필요 없다.** 측정하려는 사람이 카메라 사양이나 옷까지의 거리를 알 필요가 없다.

논문의 표현: **"모바일 기기 하나로, 누구나, 어디서나, 즉시 치수를 잴 수 있다."**

### 논문이 내세운 두 가지 이점

1. **외부 작업대 제약이 없다** (no external workbench constraints)
2. **측정점을 직접 검출한다** (direct sizing point detection) — 윤곽선 추출이나 템플릿 매칭 같은 중간 단계가 필요 없다

## 3. 사전지식 (A to Z)

### 3.1 왜 2D만으로는 안 되는가

논문 초록의 표현: "2D 이미지를 다루는 과정에서, 추정된 점들 사이의 실제 거리를 결정하는 데 제약이 생긴다."

카메라 투영에서 깊이가 사라지므로 픽셀 거리와 실제 거리의 변환 비율을 알 수 없다. 이 비율을 알려면 카메라와 대상의 거리를 고정하거나 참조물을 넣어야 한다.

→ 상세: [04_3D·PointCloud·LiDAR.md](../01_foundations/04_3D·PointCloud·LiDAR.md)의 `### 깊이 정보가 왜 필요한가`

### 3.2 포인트 클라우드

LiDAR가 레이저 펄스를 쏴서 실세계의 공간 정보를 3차원 점 집합으로 저장한 것이다. 각 점이 LiDAR로부터의 거리(깊이) 정보를 가지므로, 스캔된 공간 내 특정 점들 사이의 거리를 계산할 수 있다.

→ 상세: [04_3D·PointCloud·LiDAR.md](../01_foundations/04_3D·PointCloud·LiDAR.md)의 `### 포인트 클라우드 자료구조`

### 3.3 HRNet과 W48

고해상도 표현을 유지하면서 다중 해상도 서브네트워크를 병렬로 연결하는 자세 추정 모델이다.

**W48의 의미**: 3단계 서브네트워크의 **너비(채널 수)** 를 가리킨다. HRNet-W32보다 큰 변형이다. 이 논문은 W48을 썼다.

**왜 옷에 HRNet인가 (논문 3.1.1절)**: 저해상도 특징을 고해상도 표현으로 복원하는 데 효과적인데, **옷의 키포인트 주변 시각적 특징은 사람의 것보다 훨씬 다양하기 때문에** 이 성질이 특히 유리하다.

→ 상세: [03_비전_검출·분할·키포인트.md](../01_foundations/03_비전_검출·분할·키포인트.md)의 `### HRNet의 고해상도 유지`

### 3.4 DeepFashion2 데이터셋

의류 이미지에 카테고리·바운딩박스·랜드마크·마스크가 붙은 대규모 데이터셋이다. 13개 의류 종류, 491,000장 규모다.

이 논문은 이 중 **이미지가 5만 장 이상인 5개 카테고리**만 골라 썼다.

### 3.5 코사인 법칙

두 변의 길이와 사이 각으로 나머지 변을 구하는 공식이다. 이 논문의 거리 계산식(식 3)이 이 형태를 변형한 것이다.

LiDAR의 각 점이 **같은 각도 간격으로 투영**되므로, 두 점 사이의 각도는 점의 단위 각도에 두 점 사이의 점 간격 수를 곱해서 구할 수 있다. 이것이 이 계산법의 전제다.

## 4. 방법론 단계별 해부

### 4.1 전체 구조

논문의 표현대로 두 단계다.

```
1단계: 원하는 치수에 해당하는 측정점(sizing point)을 찾는다
        → HRNet 기반 키포인트 추정 모델로 2D 이미지에서 픽셀 좌표를 얻는다

2단계: 측정점 사이의 거리를 계산한다
        → 이미지와 깊이 맵의 좌표를 맞춰 각 측정점을 포인트 클라우드의 대응점에 매핑
        → 포인트 클라우드의 3D 공간 좌표에서 나온 깊이 정보로 실제 크기를 계산
```

### 4.2 HRNet-W48 기반 측정점 검출기

**구조 (논문 식 1)**

HRNet은 네 개의 병렬 서브네트워크 단계로 구성된다. `N_sr`에서 `s`는 단계, `r`은 해상도 인덱스다.

```
N₁₁ → N₂₁ → N₃₁ → N₄₁
   ↘ N₂₂ → N₃₂ → N₄₂
        ↘ N₃₃ → N₄₃
             ↘ N₄₄
```

- 초기 단계는 고해상도 서브네트워크 `N₁₁`에서 시작한다
- 각 서브네트워크는 두 갈래로 분기한다: 같은 해상도로 이어지는 갈래(`N₁₁ → N₂₁`)와 고해상도에서 저해상도로 가는 갈래(`N₁₁ → N₂₂`)
- 같은 `r`을 가진 네트워크끼리는 같은 해상도 수준의 표현을 유지한다

**핵심**: 모든 병렬 서브네트워크가 다른 단계의 정보를 반복적으로 교환한다. 저해상도에서 고해상도로 **복원**하는 것이 아니라, 고해상도↔저해상도의 **양방향 정보 교환**으로 풍부한 표현을 갖는다는 것이 원저자(Sun et al.)의 설명이다.

**출력과 손실 (논문 식 2)**

마지막 단계의 고해상도 출력이 각 키포인트의 히트맵을 추정한다. 손실은 정답 좌표와 추정 좌표 사이의 유클리드 거리의 평균제곱오차다.

```
MSE = (1/n) Σᵢ dᵢ²
    = (1/n) Σᵢ √( (cxᵢ − c̃xᵢ)² + (cyᵢ − c̃yᵢ)² )
```

- `(cxᵢ, cyᵢ)`: i번째 키포인트의 정답 좌표
- `(c̃xᵢ, c̃yᵢ)`: 추정 좌표
- 정답 좌표로부터의 최단 직선거리를 찾는 문제가 된다

> ※ 이 식은 표기상 특이하다. `dᵢ²`의 평균이라고 써 놓고 전개식은 `dᵢ`(제곱근이 살아 있는 형태)의 평균으로 되어 있어, 엄밀히는 MSE가 아니라 평균 유클리드 거리다. 원문 표기를 그대로 옮긴 것이며, 면접에서 이 식을 인용할 일이 있으면 **"키포인트 좌표 오차의 거리 기반 손실"** 이라고 서술하는 것이 안전하다.

### 4.4 실제 거리 계산 (논문 3.2절)

**절차**

```
1. 같은 시점·각도에서 촬영한 2D 이미지와 깊이 맵을 매핑한다
2. 검출된 각 측정점을 포인트 클라우드의 대응점에 연결한다
3. 두 점 사이의 거리와 그 사이 각도로 실제 치수를 계산한다
```

**계산식 (논문 식 3)**

```
d_ab = √( (d_b · sin θ_ab)² + (d_a − d_b · cos θ_ab)² )
```

- `d_ab`: 점 a와 점 b 사이의 직선거리
- `d_a`: LiDAR 센서로부터 점 a까지의 거리
- `d_b`: LiDAR 센서로부터 점 b까지의 거리
- `θ_ab`: 점 a와 점 b 사이의 각도

**이 식이 나오는 원리**

LiDAR의 각 점은 **같은 각도 간격으로 투영**된다. 따라서 두 점 사이의 각도는 `단위 각도 × 두 점 사이의 점 간격 수`로 구한다.

기하학적으로는 코사인 법칙과 같다. 두 변 `d_a`, `d_b`와 끼인각 `θ_ab`가 주어졌을 때 나머지 변을 구하는 것이다.

```
코사인 법칙:  d_ab² = d_a² + d_b² − 2·d_a·d_b·cos θ_ab
논문의 식:    d_ab² = (d_b sin θ)² + (d_a − d_b cos θ)²
            = d_b² sin²θ + d_a² − 2 d_a d_b cos θ + d_b² cos²θ
            = d_b²(sin²θ + cos²θ) + d_a² − 2 d_a d_b cos θ
            = d_a² + d_b² − 2 d_a d_b cos θ        ✓ 같다
```

**논문의 표현**: "줄자로 직접 재는 방식과 동일하다."

| 평가 규모 | 모델 4명 | **의류 33벌 × 660세트** | 딸기 1,010개 |
| 대표 오차 | 대부분 8% 이내 | **1.59% / 2.08%** | 폭 3.71%, 높이 5.42%, 무게 10.3% |
| 본인 위치 | 3/7 | **4/6** | 6/8 |

**T04가 셋 중 오차가 가장 작은 이유**

1. **측정 대상이 평면에 가깝다.** 펼쳐 놓은 옷은 깊이 변화가 작아 flying pixel 문제가 덜하다
2. **직선거리를 잰다.** 곡면을 따라가는 둘레보다 오차가 누적되지 않는다
3. **회귀 추정이 없다.** 잰 값이 곧 결과라 회귀식의 오차가 더해지지 않는다
4. **정답이 명확하다.** 옷의 가슴너비는 재는 기준이 분명하다. 사람의 둔부둘레와 대비된다

**이 논리는 세 논문 비교 질문에서 그대로 쓸 수 있다.**

## 5. 핵심 수식

**식 (1) — HRNet 서브네트워크 구조**

```
N₁₁ → N₂₁ → N₃₁ → N₄₁
   ↘ N₂₂ → N₃₂ → N₄₂
        ↘ N₃₃ → N₄₃
             ↘ N₄₄
```

`N_sr`에서 `s`는 단계, `r`은 해상도 인덱스다.

**식 (2) — 키포인트 손실**

```
MSE = (1/n) Σᵢ dᵢ² = (1/n) Σᵢ √( (cxᵢ − c̃xᵢ)² + (cyᵢ − c̃yᵢ)² )
```

**식 (3) — 두 3D 점 사이의 실제 거리 (핵심)**

```
d_ab = √( (d_b · sin θ_ab)² + (d_a − d_b · cos θ_ab)² )
```

- `d_a`, `d_b`: LiDAR로부터 각 점까지의 거리
- `θ_ab`: 두 점 사이 각도 = 단위 각도 × 점 간격 수

코사인 법칙과 동치다. **줄자 측정과 같은 직선거리를 구한다.**

**식 (4) — 상대오차**

```
상대오차 = 절대오차 / 실제 크기 = |실제 크기 − 추정 크기| / 실제 크기
```

### 7.2 이 표에서 읽어야 할 것

**절대 길이로 환산**하면 50cm 길이에서 각각 **0.79cm, 1.04cm** 오차다.

**② 배경 조건의 영향이 작다**

```
흰 배경판: 1.59%
맨바닥:   2.08%
```

기존 2D 방식은 배경판이 **필수**였는데, 이 방법은 배경판 없이도 2% 수준을 유지한다. **환경 통제가 필요 없다는 주장의 근거**가 이 수치다.

**앞서 말한 "매번 수거하고 다시 놓았다"는 실험 설계가 이 주장을 뒷받침한다.**

### 7.3 오차의 원인 분석 (논문 4.2절)

논문이 평균 상대오차가 부풀려진 이유를 두 가지로 설명한다.

**원인 1 — 실제 길이가 짧으면 상대오차가 과대평가된다**

```
상대오차 = 절대오차 / 실제 길이
```

소맷부리(cuff opening)나 밑단너비(leg opening)처럼 실제 길이가 짧은 항목은 같은 절대오차라도 상대오차가 커진다.

근거: **절대오차는 실험 2의 앞밑위(front rise)를 제외하면 전부 1cm 미만**이었다. 즉 절대적 정확도는 균일한데 상대오차만 항목별로 달라 보이는 것이다.

**원인 2 — 시각적 특징이 빈약한 지점의 검출 성능이 떨어진다**

문제가 된 지점:

- **티셔츠 목 뒤쪽 지점**
- **반바지와 바지의 밑위(crotch) 지점**

**근본 원인**: **DeepFashion2는 대부분 사람이 옷을 입은 이미지**로 구성돼 있다. 그래서 어떤 지점들은 **사람의 피부에 가려져 있었다.** 해당 지점에 대한 학습 데이터가 부족해 검출 위치가 조금씩 달라졌다.

**이 지적이 중요한 이유**: **학습 데이터의 도메인(입은 옷)과 추론 데이터의 도메인(펼쳐 놓은 옷)이 다르다.** 이 불일치가 특정 지점에서 성능 저하로 나타난 것이고, 8절에서 다룰 핵심 한계다.

### 7.5 LiDAR 정밀도에 대한 논문의 주장

논문 5장에 이런 문장이 있다.

> LiDAR 센서는 2D 이미지와 같은 시점에서 대상 공간까지의 거리를 **0.00001 cm 수준**으로 기록할 수 있다.

> ※ 0.00001 cm는 **0.1 마이크로미터**다. 모바일 LiDAR의 실제 측정 정확도는 통상 수 mm~cm 수준이므로, 이 수치는 **데이터 형식이 표현할 수 있는 수치 정밀도(numerical precision)** 를 말한 것이지 **측정 정확도(accuracy)** 가 아니다. 같은 계보의 T05에도 "0.0001 mm"라는 동일한 취지의 표현이 나온다. **면접에서 이 문장이 지적되면 정밀도와 정확도의 구분으로 답해야 한다.** 8.5절 참조.

## 8. 한계와 반박 대응

### 8.1 학습 데이터와 실제 사용 도메인이 다르다 — 논문 스스로 짚은 문제

DeepFashion2는 **사람이 입은 옷** 이미지가 대부분인데, 이 방법은 **바닥에 펼쳐 놓은 옷**을 측정한다.

**결과로 나타난 증상**: 목 뒤쪽, 밑위처럼 입은 상태에서 피부에 가려지는 지점의 검출 성능이 떨어졌다.

**개선 방향**

- 펼쳐 놓은 옷 이미지로 별도 데이터셋을 구축해 파인튜닝
- 문제가 되는 지점만 집중적으로 추가 라벨링
- 도메인 적응(domain adaptation) 기법 적용

**답변 전략**: 논문이 이미 원인을 정확히 짚었으므로, 그 분석을 그대로 말하고 개선안을 덧붙인다. **원인을 아는 것이 이미 절반이다.**

### 8.2 바지의 오차가 유독 크다

맨바닥에서 3.57%로 다른 종류의 두 배 수준이고, 배경 조건 변화에 가장 취약했다.

**추론 가능한 원인**

1. **밑위(crotch) 지점**이 시각적으로 모호하다 (논문이 지적)
2. **앞밑위(front rise)** 는 절대오차가 1cm를 넘은 유일한 항목이다
3. 바지는 다리 부분이 겹쳐 접히기 쉬워 펼친 상태에서도 형태 변동이 크다
4. 표본이 4벌로 다섯 종류 중 가장 적다

**답변 전략**: 논문이 밑위 지점을 명시적으로 지목했으므로 그것을 근거로 삼고, 표본 수(4벌)가 적다는 점도 함께 말한다.

### 8.3 표본이 33벌이다

660세트라는 숫자는 커 보이지만 **실제 서로 다른 옷은 33벌**이다. 나머지는 같은 옷을 반복 촬영한 것이다.

**두 숫자를 구분해야 한다.**

- **660**: 촬영 반복에 대한 강건성을 뒷받침한다 (표준오차 0.20% 미만의 근거)
- **33**: 의류 다양성에 대한 일반화를 뒷받침한다 — **이쪽이 약하다**

디자인·색상·형태가 다양하고 모두 중고 의류였다는 점은 실제 환경에 가깝다는 장점이지만, 33벌로 5개 종류를 덮기에는 종류당 4~10벌이다.

**답변 전략**: 이 구분을 스스로 짚는 것이 좋다. "반복 촬영 강건성은 660세트가 뒷받침하지만, 의류 종류의 다양성에 대한 일반화는 33벌 기준이라 근거가 제한적입니다."

### 8.4 5개 종류만 다뤘다

DeepFashion2의 13개 종류 중 5개만 썼다. **원피스, 아우터, 조끼 등은 다루지 않았다.** 선택 기준이 "이미지 5만 장 이상"이었으므로, 데이터가 적은 종류는 애초에 배제된 것이다.

실제 의류 판매에서 원피스나 코트가 차지하는 비중을 고려하면 적용 범위의 제약이 크다.

### 8.5 LiDAR 정밀도 주장이 과장돼 있다

"0.00001 cm 수준으로 기록"이라는 서술은 물리적으로 불가능하다. 0.1 마이크로미터는 광학 현미경의 분해능 수준이다.

**정확한 구분**

| 개념 | 뜻 | 모바일 LiDAR |
|------|-----|--------------|
| 정밀도(precision) | 반복 측정의 일관성, 또는 값의 표현 자릿수 | 데이터 형식은 소수점 아래 여러 자리를 담는다 |
| 정확도(accuracy) | 참값과의 근접도 | 수 mm ~ 수 cm |

**답변 전략**: 지적받으면 인정하고 정확히 구분한다. "그 표현은 데이터 형식이 담을 수 있는 수치 자릿수를 말한 것이고, 실제 측정 정확도는 아닙니다. 정밀도와 정확도를 구분하지 않은 서술이라 오해를 부를 수 있고, 더 정확하게 썼어야 한다고 봅니다."

**이 지적을 먼저 하면 오히려 신뢰를 얻는다.**

### 8.6 정답 측정의 신뢰도

팀이 3회 독립 측정해 최소·최대·중앙값을 기록했다고 밝힌 것은 **T03보다 나은 설계**다. 다만:

- 측정자가 몇 명인지, 서로 독립적이었는지 명시되지 않았다
- 최종 정답으로 중앙값을 썼는지, 세 값의 범위를 오차 분석에 활용했는지 불명확하다
- 수동 측정 오차 3.25%가 어떻게 계산됐는지(3회 측정의 편차인지, 별도 기준과의 차이인지) 원문에 명확하지 않다

**"수동 측정보다 정확하다"는 주장의 근거가 이 3.25%이므로**, 이 수치의 정의가 중요하다.

**답변 전략**: 3.25%의 정확한 정의를 원문에서 확인할 수 없다면 그렇게 말한다. "수동 측정 오차 3.25%가 어떤 기준에서 나온 값인지 논문에 명확히 서술돼 있지 않습니다. 이 수치가 주장의 핵심 근거라 정의가 더 분명했어야 합니다."

### 8.7 옷을 펼쳐 놓아야 한다

이 방법은 옷을 바닥에 펼쳐 놓는 것을 전제한다. 실제 중고 거래 상황에서는 옷걸이에 걸려 있거나 접혀 있는 경우가 많다.

Table 3에서 "접히거나 뒤틀린 부분에 대응 가능"하다고 주장하지만, 이는 **일부가 접힌 상태**를 의미하지 옷 전체가 접힌 상태를 뜻하지는 않는다.

### 8.8 추론 속도가 보고되지 않았다

실용성을 주장하는 논문인데 **추론 시간이 없다.** HRNet-W48은 비교적 무거운 모델이고, 모바일 기기에서 몇 초가 걸리는지가 사용자 경험을 좌우한다.

같은 계보의 T05가 ONNX 변환으로 iOS·Android 동작을 언급하므로, 그쪽으로 보완해 답할 수 있다.

## 10. 예상 질문

#### Q001. 이 논문을 설명해 주세요. 🟢

**의도:** 기본 확인 질문.

**답변:** 옷의 치수를 자동으로 재는 연구입니다. 기존 자동 측정은 2D 이미지 기반이라 픽셀 거리를 실제 거리로 바꾸려면 카메라 거리와 각도, 조명판, 배경판을 전부 통제해야 했습니다. 장비 설치 공간과 준비 작업이 필요해서 소규모 사업자나 일반 소비자에게는 비현실적이었습니다. 저희는 LiDAR가 달린 아이패드로 옷을 바닥에 펼쳐 놓고 한 번 촬영하는 방식을 제안했습니다. HRNet-W48로 치수 측정점을 찾고, 그 점들을 포인트 클라우드에 매핑해 두 점 사이의 실제 거리를 코사인 법칙으로 계산합니다. 중고 의류 33벌을 두 가지 배경에서 660세트 촬영했는데 평균 상대오차가 1.59퍼센트와 2.08퍼센트였습니다. 사람이 직접 잰 값의 오차가 3.25퍼센트였으니 수동 측정보다 정확했습니다.

**꼬리질문:** 사람보다 정확하다는 게 어떻게 가능합니까?

#### Q002. 사람이 직접 재는 것보다 정확하다는 게 어떻게 가능합니까? 🟡

**의도:** 주장의 근거를 이해하는지 본다.

**답변:** 사람의 수동 측정에는 두 종류의 변동이 있습니다. 하나는 측정 지점을 어디로 잡느냐이고, 다른 하나는 줄자를 얼마나 팽팽하게 당기느냐입니다. 같은 사람이 같은 옷을 세 번 재도 값이 달라집니다. 저희 팀도 각 치수를 세 번 독립적으로 재서 최소, 최대, 중앙값을 기록했는데 그 편차가 상대오차 3.25퍼센트에 해당했습니다. 자동 측정은 검출 모델이 같은 옷에 대해 항상 같은 지점을 찾고, 거리 계산에 사람 손이 개입하지 않기 때문에 반복 변동이 작습니다. 실제로 저희 결과의 표준오차가 0.20퍼센트 미만이었습니다. 다만 이 비교가 성립하려면 수동 측정 오차 3.25퍼센트가 어떻게 정의된 값인지가 명확해야 하는데, 그 부분이 논문에 충분히 서술돼 있지 않은 것은 한계라고 봅니다.

**꼬리질문:** 그럼 자동 측정의 정답은 무엇을 기준으로 삼았습니까?

#### Q003. 배경판 없이도 성능이 유지된 이유가 무엇입니까? 🟡

**의도:** LiDAR를 쓰는 이유를 정확히 아는지 확인한다.

**답변:** 기존 2D 방식이 배경판을 필요로 한 이유는 두 가지였습니다. 하나는 옷의 윤곽선을 추출하기 위해 배경과 대비를 만들어야 했고, 다른 하나는 픽셀 거리를 실제 거리로 변환할 기준이 필요했습니다. 저희 방법은 둘 다 필요 없습니다. 윤곽선을 추출하지 않고 키포인트를 직접 검출하기 때문에 배경과의 대비가 필수가 아니고, 거리는 LiDAR가 각 점까지의 실제 거리를 직접 기록하므로 변환 기준이 필요 없습니다. 결과적으로 흰 배경판 1.59퍼센트, 맨바닥 2.08퍼센트로 0.49퍼센트포인트 차이에 그쳤습니다. 다만 완전히 무관하지는 않아서, 맨바닥에서 오차가 조금 늘었고 특히 바지에서 차이가 컸습니다.

**꼬리질문:** 그럼 맨바닥에서 오차가 늘어난 건 무엇 때문입니까?

#### Q004. 두 점 사이의 실제 거리를 어떻게 계산합니까? 🟡

**의도:** 핵심 수식을 이해하는지 본다.

**답변:** 코사인 법칙을 씁니다. LiDAR로부터 점 a까지의 거리와 점 b까지의 거리를 알고, 두 점 사이의 각도를 알면 나머지 변인 두 점 사이 직선거리를 구할 수 있습니다. 각도를 구할 수 있는 이유는 LiDAR의 각 점이 같은 각도 간격으로 투영되기 때문입니다. 그래서 두 점 사이 각도는 단위 각도에 두 점 사이의 점 간격 수를 곱하면 나옵니다. 논문의 식은 이걸 사인과 코사인으로 분해한 형태인데 전개하면 코사인 법칙과 같습니다. 결과적으로 줄자로 두 지점 사이를 직선으로 재는 것과 같은 값을 얻습니다.

**꼬리질문:** 옷은 평면이 아닌데 직선거리로 재도 됩니까?

#### Q005. 옷을 펼쳐 놓아도 완전한 평면은 아닌데 직선거리로 재는 게 맞습니까? 🔴

**의도:** 방법의 가정을 짚는다.

**답변:** 엄밀히 말하면 근사입니다. 다만 두 가지가 이 근사를 정당화합니다. 첫째, 사람이 줄자로 재는 방식도 두 지점 사이를 직선으로 당겨 재는 것이라 기준이 같습니다. 의류 치수 표기 자체가 그렇게 정의돼 있습니다. 둘째, 펼쳐 놓은 옷은 깊이 변화가 작아서 두 점의 깊이 차이가 크지 않고, 그래서 직선거리와 표면을 따라간 거리의 차이가 작습니다. 반면 사람 몸의 둘레를 잴 때는 이 근사가 성립하지 않아서, 같은 계보의 인체 계측 논문에서는 인접 픽셀 거리를 누적해 곡면을 따라가는 방식을 썼습니다. 대상의 성질에 따라 계산 방식을 다르게 가져간 것입니다.

**꼬리질문:** 그럼 옷이 심하게 구겨져 있으면 어떻게 됩니까?

#### Q006. 데이터 증강에서 대칭점을 교환했다고 하셨는데 왜 그게 필요합니까? 🟡

**의도:** 실무 디테일을 아는지 확인한다.

**답변:** 좌우 반전 증강을 할 때 이미지만 뒤집고 레이블을 그대로 두면 학습이 망가지기 때문입니다. 왼쪽 겨드랑이 지점을 뒤집으면 이미지상으로는 오른쪽에 있게 되는데, 레이블이 여전히 왼쪽 겨드랑이라고 되어 있으면 모델은 모순된 신호를 받습니다. 그래서 반전과 함께 좌우 대칭인 키포인트 쌍의 레이블도 서로 바꿔 줘야 합니다. 이 아이디어는 의류 랜드마크 추정 대회 1위 모델에서 가져온 것이고, 3위 모델에서는 특정 의류 종류의 데이터가 부족하면 전체 성능이 떨어진다는 지적을 참고해서 데이터가 부족한 종류는 학습에서 제외했습니다.

**꼬리질문:** 데이터가 부족한 종류를 제외하면 그 종류는 아예 측정을 못 하는 것 아닙니까?

#### Q007. 학습에는 DeepFashion2를 쓰고 실제로는 펼쳐 놓은 옷을 측정하는데, 도메인이 다르지 않습니까? 🔴

**의도:** 이 논문의 핵심 한계를 짚는다. 논문 스스로 인정한 부분이라 알아야 한다.

DeepFashion2는 대부분 사람이 옷을 입은 이미지로 구성돼 있는데, 저희는 바닥에 펼쳐 놓은 옷을 측정합니다. 그 결과 입은 상태에서 피부에 가려지는 지점들, 구체적으로 티셔츠 목 뒤쪽과 반바지나 바지의 밑위 지점에서 검출 성능이 떨어졌습니다. 해당 지점에 대한 학습 데이터가 사실상 부족했던 것입니다. 바지의 상대오차가 다른 종류의 두 배 가까이 나온 것도 이 문제와 연결됩니다. 개선하려면 펼쳐 놓은 옷 이미지로 별도 데이터셋을 만들어 파인튜닝하거나, 문제가 되는 지점만 집중적으로 추가 라벨링하는 방법이 있습니다.

**꼬리질문:** 그 데이터셋을 실제로 만드셨습니까?

#### Q008. 왜 바지에서 오차가 가장 컸습니까? 🟡

**의도:** 결과를 원인과 연결해 설명하는지 본다.

**답변:** 세 가지가 겹친 것으로 봅니다. 첫째, 논문이 지적한 밑위 지점의 시각적 모호성입니다. 밑위는 두 다리가 갈라지는 지점인데 학습 데이터에서 가려져 있던 경우가 많아 검출이 불안정했습니다. 실제로 절대오차가 1센티미터를 넘은 유일한 항목이 실험 2의 앞밑위였습니다. 둘째, 바지는 다리 부분이 겹쳐 접히기 쉬워서 펼쳐 놓아도 형태 변동이 다른 종류보다 큽니다. 셋째, 표본이 4벌로 다섯 종류 중 가장 적습니다. 맨바닥에서 3.57퍼센트로 유일하게 3퍼센트를 넘었고 배경 조건 변화에 대한 악화 폭도 가장 컸는데, 이 세 요인이 함께 작용한 결과로 읽었습니다.

**꼬리질문:** 그럼 바지는 이 방법으로 못 재는 겁니까?

#### Q009. 660세트라고 하셨는데 실제로는 옷이 33벌뿐 아닙니까? 🔴

**의도:** 표본 수를 부풀려 말하는지 시험한다.

**답변:** 맞습니다. 두 숫자를 구분해서 봐야 합니다. 660세트는 33벌을 벌당 10회씩, 두 가지 배경 조건에서 촬영한 것입니다. 이 숫자가 뒷받침하는 것은 반복 촬영에 대한 강건성입니다. 매번 옷을 수거하고 다시 놓아서 위치와 형태가 조금씩 달라진 상태로 찍었는데, 그럼에도 상대오차의 표준오차가 0.20퍼센트 미만이었습니다. 반면 의류 다양성에 대한 일반화는 33벌 기준이고, 종류당 4벌에서 10벌이라 근거가 제한적입니다. 디자인과 색상이 다양했고 전부 중고 의류였다는 점은 실제 환경에 가깝다는 장점이지만, 종류별 표본이 더 필요하다고 봅니다.

**꼬리질문:** 몇 벌 정도면 충분하다고 보십니까?

#### Q010. LiDAR가 0.00001 센티미터 수준으로 거리를 기록한다고 논문에 적혀 있는데 그게 가능합니까? 🔴

**의도:** 논문의 과장된 표현을 짚는다. 물리적 상식을 확인하는 질문이다.

**답변:** 물리적으로 불가능한 수치입니다. 0.00001 센티미터는 0.1 마이크로미터인데, 광학 현미경의 분해능 수준입니다. 모바일 LiDAR의 실제 측정 정확도는 통상 수 밀리미터에서 수 센티미터 수준입니다. 그 문장은 데이터 형식이 담을 수 있는 수치 자릿수, 즉 정밀도를 말한 것이지 참값과의 근접도인 정확도를 말한 것이 아닙니다. 정밀도와 정확도를 구분하지 않은 서술이라 오해를 부를 수 있고, 더 정확하게 표현했어야 한다고 생각합니다. 같은 계보의 딸기 논문에도 0.0001 밀리미터라는 같은 취지의 표현이 나오는데, 두 논문 모두 수정이 필요한 부분입니다.

**꼬리질문:** 그럼 실제 LiDAR의 거리 측정 오차는 얼마 정도입니까?

#### Q011. 5개 의류 종류만 다루셨는데 원피스나 코트는 왜 없습니까? 🟡

**의도:** 적용 범위의 제약을 인식하는지 본다.

**답변:** 학습 데이터의 제약 때문입니다. DeepFashion2가 13개 의류 종류를 담고 있지만 종류별 데이터 양의 편차가 컸습니다. 딥러닝 모델이 각 종류의 시각적 특징을 학습하고 일반화하려면 종류마다 충분한 데이터가 필요해서, 이미지가 5만 장 이상인 다섯 종류만 골랐습니다. 반팔 상의, 긴팔 상의, 반바지, 바지, 치마입니다. 실제 의류 판매에서 원피스나 아우터가 차지하는 비중을 생각하면 적용 범위의 제약이 분명합니다. 이 부분은 자체 데이터를 구축해서 확장해야 하는 지점이고, 이후 실무 과제에서 다뤘던 방향이기도 합니다.

**꼬리질문:** 자체 데이터를 구축한다면 몇 장 정도가 필요하다고 보십니까?

#### Q012. 추론 시간이 논문에 없는데 실용성을 어떻게 주장할 수 있습니까? 🔴

**의도:** 실용성 주장의 근거가 빠진 것을 짚는다.

**답변:** 지적하신 대로 추론 시간이 보고되지 않았습니다. 실용성을 내세우는 논문에서 빠져서는 안 되는 정보라고 생각합니다. HRNet-W48은 HRNet 계열 중에서도 비교적 큰 모델이라 모바일에서의 속도가 사용자 경험을 좌우합니다. 논문이 실용성의 근거로 든 것은 속도가 아니라 환경 통제가 필요 없다는 점, 즉 장비 설치와 배경판, 캘리브레이션이 불필요하다는 점이었습니다. 그 부분은 Table 3에서 기존 방법과 비교해 명확히 보였습니다. 다만 속도까지 포함해야 완결된 주장이 됩니다. 같은 계보의 딸기 논문에서는 ONNX로 변환해 iOS와 안드로이드에서 클라우드 없이 동작하는 소프트웨어를 만들었다고 밝혔는데, 그쪽이 모바일 실행 가능성에 대한 더 직접적인 근거입니다.

**꼬리질문:** 그럼 이 모델을 모바일에 올리려면 무엇을 하셔야 합니까?

#### Q015. 세 편의 3D 계측 논문 중에서 이 논문의 오차가 가장 작은데 왜 그렇습니까? 🟡

**의도:** 세 논문을 비교해 설명할 수 있는지 본다. 반드시 나오는 질문이다.

**답변:** 네 가지 이유가 있다고 봅니다. 첫째, 측정 대상이 평면에 가깝습니다. 펼쳐 놓은 옷은 깊이 변화가 작아서, 깊이 센서가 물체 경계에서 물체와 배경의 거리를 섞어 기록하는 문제가 덜합니다. 둘째, 직선거리를 잽니다. 인체 논문처럼 곡면을 따라가는 둘레를 구하면 픽셀마다 오차가 누적되는데 직선거리는 두 점만 정확하면 됩니다. 셋째, 회귀 추정이 없습니다. 잰 값이 곧 결과라서 딸기의 무게나 인체의 둘레처럼 회귀식의 오차가 더해지지 않습니다. 넷째, 정답이 명확합니다. 옷의 가슴너비는 재는 기준이 분명한데, 사람의 둔부둘레는 어디서 시작하고 끝나는지가 재는 사람마다 다릅니다. 정답 자체의 흔들림이 작다는 뜻입니다.

**꼬리질문:** 그럼 인체 측정에서 오차를 줄이려면 어떻게 해야 합니까?
