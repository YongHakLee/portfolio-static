# T03 — 모바일 LiDAR 기반 실시간 3D 인체 계측

> **A Mobile LiDAR-Based Deep Learning Approach for Real-Time 3D Body Measurement**
> Applied Sciences, 2025, 15(4), 2001 · 공저(3/7)

---

## 0. 30초 요약

> 스마트폰에 들어간 LiDAR 센서로 사람의 신체 둘레를 자동으로 재는 연구입니다. 기존 3D 인체 복원 모델인 SMPL이나 PIFu는 정밀하지만 고성능 GPU가 필요하고 옷을 입은 상태를 다루기 어려워 모바일에서 실시간으로 쓸 수 없었습니다. 저희는 3D 메시를 복원하지 않는 가벼운 방식을 택했습니다. HRNet으로 신체 지점을 찾고, 깊이 맵에 Canny 엣지를 적용해 그 지점을 실제 물체 경계로 끌어온 뒤, 3차원 유클리드 거리만 계산합니다. 정면과 측면에서 잰 둘레를 회귀식으로 합쳐 전체 둘레를 추정했는데, 이 회귀 상수는 한국인 남성 150명의 실측값에서 구했습니다. 결과는 대부분 부위에서 상대오차 8% 이내였고, 보정 알고리즘의 효과가 컸습니다. 보정 없이 LiDAR만 쓰면 19.2%였던 오차가 보정을 넣어 5.2%로 떨어졌습니다.

## 2. 왜 이 연구를 했나

### 문제 상황

온라인으로 옷을 살 때 자기 신체 치수를 알아야 하는데, 지금까지는 사용자가 직접 줄자로 재야 했다. 번거롭고, 재는 방법에 따라 값이 달라진다.

기존 자동 측정은 크게 두 갈래였다.

| 방식 | 한계 |
|------|------|
| 2D 이미지 기반 | 깊이 정보가 없어 실제 거리를 알 수 없다. 참조물과 통제된 촬영 환경이 필요하다 |
| 수동 측정 | 시간이 걸리고 사용자에게 불편하다 |

### 기존 3D 복원 모델을 쓰지 않은 이유 — 논문 2.4절의 핵심

논문은 3D 메시 복원 계열 모델 세 가지를 구체적으로 검토하고 각각 왜 부적합한지 밝힌다. **이 부분이 이 연구의 위치를 규정하므로 반드시 알아야 한다.**

| 모델 | 방식 | 이 과제에 부적합한 이유 |
|------|------|------------------------|
| **SMPL** | 파라메트릭 인체 모델 | **나체 체형으로 학습**된 모델이라 옷을 입었을 때의 체형·둘레 변화를 반영하기 어렵다. 단일 이미지에서 파라미터(β, θ)를 추정하려면 복잡한 피팅 절차와 고성능 GPU가 필요해 실시간이 사실상 불가능하다 |
| **PIFu** | 암시적 함수로 고해상도 표면 복원 | 옷 주름 같은 세부는 잘 잡지만, **단일 시점에서 뒷면이나 가려진 영역을 정확히 추정하기 어렵다.** 보통 다중 시점 촬영과 상당한 연산 자원이 필요해 일반 모바일 기기에 부적합하다 |
| **DeepHuman** | 복셀 기반 3D 복원 | 해상도를 올리면 **GPU 메모리와 연산량이 지수적으로 증가**한다. 단일 시점에서 보이지 않는 영역을 추론해야 해 오차가 커진다 |

### 이 논문의 해법

**3D 메시 복원을 아예 하지 않는다.**

```
기존: 이미지 → 3D 메시 복원 → 메시에서 둘레 계산   (무겁다)
제안: 이미지 → 2D 키포인트 → 깊이로 3D 좌표 → 유클리드 거리   (가볍다)
```

논문 표현 그대로: HRNet 같은 고해상도 2D 자세 추정 네트워크로 측정 영역을 빠르게 특정하고, **3D 공간에서 단순 유클리드 거리만 계산한다.** 복잡한 3D 메시 복원이 필요 없으면서도 깊이 데이터를 활용해 낮은 연산 비용으로 정확한 둘레 측정이 가능하다.

### 논문이 내세운 기여

1. 전용 3D 장비 없이 모바일 기기의 LiDAR 센서만으로 3D 길이를 정확히 재는 기술
2. **깊이 맵을 이용한 2D 키포인트 보정 방법**
3. 경량 처리를 통한 실시간성 확보

## 3. 사전지식 (A to Z)

### 3.1 왜 2D 사진만으로는 실제 크기를 알 수 없는가

카메라가 3차원을 2차원에 투영하면서 깊이가 사라진다. 작은 물체가 가까이 있는 것과 큰 물체가 멀리 있는 것이 같은 사진을 만든다(스케일 모호성).

→ 상세: [04_3D·PointCloud·LiDAR.md](../01_foundations/04_3D·PointCloud·LiDAR.md)의 `### 깊이 정보가 왜 필요한가`

### 3.2 LiDAR와 깊이 맵

레이저를 쏘고 반사광이 돌아오는 시간으로 거리를 잰다. 각 픽셀에 거리 값이 담긴 이미지가 깊이 맵이다. 이 논문은 **iPhone 12 Pro**의 LiDAR를 쓴다.

→ 상세: [04_3D·PointCloud·LiDAR.md](../01_foundations/04_3D·PointCloud·LiDAR.md)의 `### LiDAR와 ToF 센서의 원리`, `### 깊이 맵`

### 3.3 HRNet과 키포인트 검출

고해상도 표현을 처음부터 끝까지 유지하면서 저해상도 브랜치와 정보를 주고받는 자세 추정 모델이다. 위치 정밀도가 그대로 측정 오차가 되는 과제라 이 성질이 중요하다.

→ 상세: [03_비전_검출·분할·키포인트.md](../01_foundations/03_비전_검출·분할·키포인트.md)의 `### HRNet의 고해상도 유지`, `### 히트맵 회귀`

### 3.4 전이학습

기본 HRNet은 표준 자세 추정용 관절만 검출한다. 가슴·허리·엉덩이 같은 **측정용 키포인트는 정의돼 있지 않다.** 그래서 새 데이터로 뒤쪽 층을 추가 학습시켜 키포인트 종류를 확장했다.

→ 상세: [02_딥러닝·CNN_기초.md](../01_foundations/02_딥러닝·CNN_기초.md)의 `### 전이학습과 파인튜닝`

### 3.5 Canny 엣지 검출

이미지에서 밝기가 급격히 변하는 경계를 찾는 고전 알고리즘이다. 절차는 **잡음 제거(가우시안 블러) → 기울기 크기·방향 계산 → 비최대 억제로 얇게 만들기 → 두 개의 임계값으로 이력 추적** 순이다.

**이 논문에서의 용도가 특이하다.** 보통 RGB 이미지의 밝기 경계를 찾는 데 쓰는데, 여기서는 **깊이 맵**에 적용해 **깊이가 급변하는 지점**, 즉 물체와 배경의 경계를 찾는다.

### 3.6 flying pixel — 이 연구가 푸는 핵심 문제

깊이 센서의 한 측정 점이 물체 가장자리에 걸치면, 물체까지의 거리와 배경까지의 거리가 섞인 중간값이 기록된다. 측정 기준점이 대부분 경계에 있으므로 **하필 가장 오차가 큰 곳에서 값을 읽어야 한다.**

→ 상세: [04_3D·PointCloud·LiDAR.md](../01_foundations/04_3D·PointCloud·LiDAR.md)의 `### 모바일 LiDAR의 특성과 한계`

### 3.7 회귀 분석

정면 둘레와 측면 둘레로부터 전체 둘레를 추정하는 데 쓴다. 단순 선형 회귀이며, 상수 하나를 곱하는 형태다.

→ 상세: [01_통계·머신러닝_기초.md](../01_foundations/01_통계·머신러닝_기초.md)의 `### 선형회귀`, `### 회귀 평가지표 (MAE·RMSE·MAPE·R²)`

## 4. 방법론 단계별 해부

### 4.1 전체 흐름 (논문 Figure 2)

논문은 전체 과정을 다섯 단계로 나눈다.

```
① Data Collection
   모바일 기기가 LiDAR로 RGB + 깊이 데이터를 촬영
        ↓
② Preprocessing
   엣지 검출, 노이즈 필터링, HRNet으로 키포인트 추출
        ↓
③ Keypoint Detection & Correction
   깊이 맵 분석으로 키포인트를 식별하고 정교화
        ↓
④ Circumference Calculation
   정면·측면에서 둘레를 재고 회귀 기반 보정 적용
        ↓
⑤ Final Output
   피트니스·의류·헬스케어용 3D 신체 치수 산출
```

길이 측정 자체는 **세 단계**다.

1. 정면·측면 사진에서 측정할 부위의 끝점을 검출
2. 검출된 끝점 사이의 둘레를 계산
3. 정면과 측면 결과를 통합해 전체 둘레를 추정

### 4.2 1단계 — HRNet 전이학습으로 키포인트 확장

**문제**: 기본 HRNet은 표준 자세 추정용 관절만 제공해, 둘레 측정에 필요한 끝점을 다 덮지 못한다.

**해법**: 전이학습.

| 항목 | 내용 |
|------|------|
| 데이터 | **사람 이미지 1,000장** |
| 분류 | 상체 / 하체 두 그룹 |
| 상체 라벨 | 가슴(chest), 허리(waist) 끝점 |
| 하체 라벨 | 엉덩이(hip), 둔부(buttock) 끝점 |
| 전체 라벨 항목 | chest, waist, buttock, hips, **femoral condyles(대퇴골 과)** |
| 학습 방식 | 사전학습 HRNet의 **마지막 몇 개 층만 재학습** |
| 검증 | 검증 데이터셋으로 성능 평가, 하이퍼파라미터 조정 |

**마지막 몇 층만 학습시킨 이유**: 데이터가 1,000장뿐이므로 전체를 파인튜닝하면 과적합된다. 앞쪽 층의 일반적 시각 특징은 유지하고 출력 부분만 새 키포인트에 맞춘다.

### 4.3 2단계 — 둘레 계산

**두 점 사이 거리 (식 1)**

```
d(k₁, k₂) = √( (x₂ − x₁)² + (y₂ − y₁)² )
```

- `k₁ = (x₁, y₁)`, `k₂ = (x₂, y₂)`: 검출된 두 키포인트

**두 점 사이 곡선 둘레 (식 2)**

두 점의 y좌표가 같다는 가정 하에, x 방향으로 인접 픽셀 사이의 거리를 모두 더해 둘레를 근사한다.

```
circum(x₁, x₂) = d(x₁, x₁+1) + d(x₁+1, x₁+2) + ... + d(x₂−1, x₂)
```

**읽는 법**: 직선거리가 아니라 **물체 표면을 따라가는 길이**를 구하려는 것이다. 픽셀 하나씩 이동하며 그 사이의 3차원 거리를 누적하면 곡면을 따라간 길이가 된다. 신체는 곡면이므로 이 방식이 필요하다.

### 4.4 3단계 — 2D 키포인트와 3D 경계의 불일치 (이 논문의 핵심 기여)

**문제 정의**

2D 이미지에서 검출한 키포인트는 3D 공간의 실제 위치와 대응하지 않는다. 카메라 시점에서 관찰되는 경계면(2D 키포인트)이 물체의 실제 윤곽을 나타내는 경계면(3D 키포인트)과 일치하지 않기 때문이다.

논문은 허리 측정을 **위에서 내려다본 단면**으로 단순화해 이 관계를 기하학적으로 정식화한다.

```
        3D Keypoint (실제 허리 표면)
   2D Keypoint  ↖
        ●━━━━━━━●  ← l (두 지점의 차이)
              ╱
             ╱ r (허리 단면의 반지름)
            ●  중심
      θ    ╱
  카메라 ●───────  d (카메라~중심 거리)
```

**기호 정의 (논문 그대로)**

- `l`: 이미지에서 검출된 2D 키포인트와 실제 3D 키포인트의 불일치로 생기는 둘레 오차
- `r`: 원(물체)의 반지름
- `θ`: 카메라 시점에서 2D 키포인트를 잇는 선과 원 중심을 잇는 선 사이의 각
- `d`: 카메라와 원 중심 사이의 거리

**유도 (식 3)**

```
sin θ = r / d
θ = arcsin(r / d)
l = r·θ = r × arcsin(r / d)
```

> ※ 원문 식 (3)의 마지막 줄은 `l = rθ = r × arcsin(r/l)`로 인쇄돼 있으나, 본문 서술은 두 번에 걸쳐 `r × arcsin(r/d)`라고 명시한다. **분모의 `l`은 `d`의 오타**다. 면접에서 이 식을 쓸 일이 있으면 `arcsin(r/d)`가 맞다.

**의미**: 한쪽만 보아도 추정 둘레가 최소 `l`만큼 차이 난다. 따라서 **2D 키포인트에서 구한 정면 둘레와 후면 둘레를 단순히 더하면 실제 둘레와 반드시 어긋난다.**

**해법 두 가지**

이 문제에 대해 논문은 두 가지를 동시에 적용한다.

1. **깊이 맵 기반 키포인트 보정** — 키포인트를 실제 경계로 끌어온다 (4.5절)
2. **회귀 분석** — 정면 둘레와 측면 둘레를 변수로 전체 둘레를 추정한다 (4.6절)

### 4.5 깊이 맵 기반 키포인트 보정 — 구체적 절차

**핵심 발상**: 깊이 맵에서 깊이가 급격히 변하는 곳이 물체의 실제 경계다. 키포인트를 그 경계로 옮긴다.

**절차**

```
1. iPhone LiDAR로 RGB와 같은 장면의 깊이 맵을 생성한다
   (값이 낮을수록 가깝고, 높을수록 멀다)

2. 깊이 맵에 Canny 엣지 알고리즘을 적용해
   깊이 값이 급변하는 지점을 검출한다 → 물체의 경계면

3. RGB 이미지에서 검출한 키포인트 좌표를
   깊이 맵 좌표계로 변환(스케일 조정)한다

4. 각 키포인트를 변환된 좌표 근처의 가장 가까운 엣지 점으로 이동시킨다
```

**해상도와 스케일 (논문의 구체 수치)**

| 항목 | 값 |
|------|-----|
| RGB 이미지 해상도 | **1440 × 1920** |
| 깊이 맵 해상도 | **192 × 256** |
| 스케일 계수 | **7.5** (1440 ÷ 192 = 7.5, 1920 ÷ 256 = 7.5) |

**보정 효과 (논문 Figure 7)**

| 상태 | 인접 픽셀 간 거리 값 |
|------|---------------------|
| 보정 전 (원기둥·마네킹) | **12 cm를 초과**하는 값이 관찰됨 → 물체 내부가 아니라 물체와 배경 사이의 거리 |
| 보정 후 | **최댓값이 1 cm를 넘지 않음** |

**이 수치가 보정 효과의 직접적 증거다.** 보정 전에는 키포인트가 물체 밖(배경)에 찍혀 있어 인접 픽셀 사이에 12cm 이상의 깊이 점프가 나타났고, 보정 후에는 모든 점이 물체 표면 위에 있어 1cm 이내로 매끄러워졌다.

### 4.6 회귀 분석으로 전체 둘레 추정

**모델 (식 4)**

```
Ct = β(Cf + Cs) + ε
```

- `Ct`: 전체 신체 둘레 (실제값, 종속변수)
- `Cf`: 정면 둘레 (독립변수)
- `Cs`: 측면 둘레 (독립변수)
- `β`: 회귀계수 (도출된 상수)
- `ε`: 오차항

**왜 이 형태인가 — 설계 판단의 근거**

처음에는 정면과 측면에 **각각 다른 상수**를 적용하는 방식(`α₁Cf + α₂Cs`)을 썼다. 그런데 실제 허리둘레로 참가자를 **마른 체형(72cm 이하)** 과 **비만 체형(95cm 이상)** 으로 나눠 비교했더니, 양쪽 극단 체형에서 평균 오차와 결정계수가 모두 나빠졌다.

논문의 해석: **`Cf`와 `Cs`는 독립이 아니라 같은 신체의 부분이라 서로 영향을 준다.** 따라서 둘을 먼저 더한 뒤 하나의 상수를 곱하는 방식으로 바꿨다.

**결과 (논문 Table 1)**

| 방법 | MAE (cm) | R² |
|------|----------|-----|
| 개별 상수 방식 (α₁Cf + α₂Cs) | 6.8 | 0.76 |
| **합산 후 상수 방식 (β(Cf + Cs))** | **5.2** | **0.84** |

**부위별 회귀 상수 (식 5)**

| 부위 | 상수 β |
|------|--------|
| 허리(Waist) | **1.32** |
| 가슴(Chest) | **1.427** |
| 엉덩이(Hip) | **1.322** |
| 둔부(Buttock) | **1.53** |

**상수의 출처**: **한국인 남성 참가자 150명**의 실측 둘레값으로부터 최적 회귀 상수를 결정했다.

> ※ 주의 — 결과 표(Table 6·7)의 캡션은 둔부에 1.322를, 엉덩이에 1.53을 적용했다고 되어 있어 **식 (5)와 배정이 서로 바뀌어 있다.** 표의 수치로 역산하면 Table 6은 1.322, Table 7은 1.53을 쓴 것이 맞다. 어느 쪽이 오기인지는 원문만으로 판정할 수 없으므로, 면접에서는 "허리 1.32, 가슴 1.427이고 엉덩이·둔부는 1.322와 1.53인데 논문 내 표기가 엇갈린다"고 말하는 것이 안전하다.

## 5. 핵심 수식

**식 (1) — 2D 유클리드 거리**

```
d(k₁, k₂) = √( (x₂ − x₁)² + (y₂ − y₁)² )
```

**식 (2) — 곡면을 따라간 둘레**

```
circum(x₁, x₂) = d(x₁, x₁+1) + d(x₁+1, x₁+2) + ... + d(x₂−1, x₂)
```

인접 픽셀 사이 거리를 누적한다. 직선이 아니라 표면을 따라가는 길이를 구한다.

**식 (3) — 2D·3D 키포인트 불일치량**

```
sin θ = r / d
θ = arcsin(r / d)
l = r·θ = r × arcsin(r / d)
```

- `r`: 신체 단면의 반지름
- `d`: 카메라~중심 거리
- `l`: 한쪽에서 생기는 둘레 오차

**읽는 법**: `r/d`가 클수록(가까이서 찍거나 대상이 굵을수록) 불일치가 커진다. 이 식은 오차가 **기하학적으로 불가피하다**는 것을 보이는 근거이지, 오차를 보정하는 식이 아니다. 실제 보정은 깊이 맵 엣지로 한다.

**식 (4) — 전체 둘레 회귀**

```
Ct = β(Cf + Cs) + ε
```

**식 (5) — 부위별 상수**

```
Waist   : (Front + Side) × 1.32
Chest   : (Front + Side) × 1.427
Hip     : (Front + Side) × 1.322
Buttock : (Front + Side) × 1.53
```

**상수의 의미**: 정면과 측면 둘레의 합이 실제 전체 둘레의 몇 배인가를 나타낸다. 1.32라는 값은 "정면·측면 합에 32%를 더해야 실제 둘레가 된다"는 뜻이고, 그 차이가 바로 카메라 시점에서 보이지 않는 부분과 2D·3D 불일치를 메우는 몫이다.

- **둔부**에서 Model 1과 2가 각각 **7.8%, 7.4%** 로 상대적으로 높았다. 논문의 해석: **둔부 영역의 복잡한 3D 구조와 키포인트 위치 선정의 어려움**
- 엉덩이는 전원 2.6% 이내로 알고리즘의 안정성을 확인

> ※ **초록과 본문이 서로 어긋난다.** 초록은 "허리와 **둔부**가 4% 이하", "**엉덩이** 측정에서 7.8%와 7.4%"라고 쓰지만, 결과 본문과 Table 6·7은 정반대다(**둔부**가 7.8%/7.4%, **엉덩이**가 2.6% 이내). **초록에서 hip과 buttock이 뒤바뀐 것**으로 보인다. 면접에서 초록만 읽고 온 면접관이 "둔부가 정확했다면서요"라고 물으면 표 기준으로 정정할 수 있어야 한다.

### 7.3 보정 효과의 정량 근거

이 논문에서 가장 설득력 있는 수치는 결과 표가 아니라 **제거 실험(Table 2)** 이다.

```
LiDAR만 (보정 없음)  →  19.2%
LiDAR + 보정        →   5.2%
                      ─────────
                      오차 약 1/4로 감소
```

그리고 **Figure 7의 12cm → 1cm**가 보정이 실제로 무엇을 했는지를 직접 보여 준다.

### 7.4 논문의 결론 네 가지

1. **정확성과 실용성**: 대부분 부위 상대오차 8% 이내로 기존 2D 방식보다 높은 정확도
2. **깊이 맵을 이용한 2D 키포인트 보정 방법 제안**: 카메라 각도와 조명 변화의 영향을 완화
3. **경량 처리를 통한 실시간성**: 2D 키포인트 검출 후 유클리드 거리만 계산해 연산 부담 감소
4. **응용과 한계**: 피트니스·헬스케어·의류에 적용 가능하나, 일부 부위 오차가 다소 높고 **표본이 제한적**이다. 향후 다양한 국적·인종으로 표본을 넓혀야 한다

## 8. 한계와 반박 대응

### 8.1 최종 평가 표본이 4명뿐이다 — 가장 큰 약점

회귀 상수는 150명에서 구했지만, **실제 성능 평가는 모델 4명**이다. 부위당 4개 데이터로 "상대오차 8% 이내"를 주장하는 셈이다.

논문 스스로 "실험이 제한된 표본으로 수행됐다"고 한계에 적었지만, 4명은 통계적 주장을 뒷받침하기에 매우 부족하다. 표준편차나 신뢰구간도 없다.

**답변 전략**: 인정하고 구조를 설명한다. "회귀 상수 도출에는 150명을 썼고 검증은 4명입니다. 회귀식의 신뢰성은 150명이 뒷받침하지만, 파이프라인 전체의 성능 주장은 4명 기준이라 근거가 약합니다. 이 부분은 논문에서도 한계로 명시했고, 검증 표본을 늘리는 것이 최우선 과제입니다."

### 8.2 회귀 상수가 한국인 남성 150명에서 나왔다

**일반화 문제가 두 층위로 있다.**

1. **성별**: 남성만으로 구했다. 여성은 체형 비율이 달라 같은 상수가 맞을 이유가 없다. **논문에 여성 데이터에 대한 언급이 없다**
2. **인종·국적**: 논문은 "이 상수가 다양한 인종과 국적에서도 일정 수준의 정확도를 유지할 수 있다"고 서술하지만, 그 근거는 **마른 체형과 비만 체형에서 성능이 유지됐다**는 것뿐이다. 체형 범위와 인종 차이는 다른 문제다

논문도 이를 인식해 "이 발견을 철저히 검증하려면 광범위한 인종·국적을 포괄하는 대규모 데이터셋을 구축해야 한다"고 적었다.

**답변 전략**: "상수가 한국인 남성 데이터에서 나왔다는 것이 이 방법의 적용 범위를 규정합니다. 여성이나 다른 인종에 그대로 쓸 수 있다는 근거는 논문에 없습니다. 실제 서비스로 만든다면 집단별로 상수를 따로 추정하거나, 상수를 고정하지 않고 개인의 다른 측정값으로 보정하는 구조가 필요하다고 봅니다."

### 8.3 회귀 상수 방식 자체의 한계

`Ct = β(Cf + Cs)`는 **모든 사람의 단면 형태가 비슷하다**고 가정하는 것과 같다. 실제로는 같은 정면·측면 둘레를 가져도 단면이 더 납작하거나 더 둥근 사람이 있고, 그 경우 실제 둘레가 달라진다.

즉 **이 방법은 단면의 모양 정보를 쓰지 않는다.** 정면 폭과 측면 폭 두 숫자로만 둘레를 추정하므로, 타원 근사보다 정보가 적다.

**대응 논리**: 그럼에도 R² 0.84가 나온 것은 실제 인체 단면의 형태 변이가 크지 않다는 뜻이다. 다만 형태가 특이한 사람에게서 오차가 커질 것이고, 둔부에서 오차가 컸던 것도 이 지점과 연결될 수 있다.

### 8.4 실제 시연에서 키포인트를 수동으로 선택했다

논문 4장(Actual Model Measurement)에 이런 서술이 있다.

> Figure 9는 RGB 이미지에서 **수동으로 검출한 임의의 키포인트**를 보여 준다. 먼저 키포인트를 수동으로 선택한 다음 딥러닝으로 자동 보정하는 과정이다. 보정 효과를 더 분명히 보이기 위해 수동 선택한 키포인트를 경계에서 약간 벗어나게 표시했다.

**문제**: 이 부분만 보면 **보정 알고리즘의 효과를 보이기 위한 시연**이고, HRNet 자동 검출을 쓰지 않았다. 그렇다면 Table 4~7의 결과가 자동 검출 기준인지 수동 선택 기준인지가 불분명해진다.

**답변 전략**: 정직하게 구분한다. "Figure 9는 보정 알고리즘의 동작을 시각적으로 보이기 위해 키포인트를 일부러 경계에서 벗어나게 수동 배치한 시연입니다. 전체 파이프라인은 HRNet 자동 검출을 전제로 하지만, 결과 표가 어느 쪽 기준인지가 논문에 명시돼 있지 않은 것은 사실입니다. 이 부분은 서술이 더 명확했어야 합니다."

### 8.5 "실시간"의 근거가 워크스테이션 기준이다

0.7초는 RTX 3090 두 장이 달린 시스템에서 측정한 값이다. 논문의 목표는 모바일 기기인데, **모바일에서의 실제 속도는 보고되지 않았다.**

**대응 논리**: 연산 구조상 무거운 부분은 HRNet 추론뿐이고 나머지는 CPU 유클리드 거리 계산이므로, 모바일에서도 감당 가능한 범위라는 것이 논문의 논지다. 다만 이는 논리적 추정이지 측정값이 아니다. T05가 ONNX 변환으로 iOS·Android에서 실제 동작하는 소프트웨어를 만들었다고 밝히므로, 그쪽을 근거로 보완할 수 있다.

### 8.7 자세 변동과 촬영 조건

둘레 측정은 정면과 측면 두 번 촬영해야 하는데, 그 사이에 자세가 바뀌면 오차가 생긴다. 숨을 들이쉬었는지, 배에 힘을 줬는지에 따라 허리둘레는 수 cm 변한다. **논문은 촬영 프로토콜(자세 지시, 호흡 상태)을 명시하지 않았다.**

### 8.8 정답(ground truth)의 신뢰도

150명과 4명의 실측값이 어떻게 측정됐는지, 반복 측정을 했는지, 측정자 간 차이를 확인했는지가 원문에 없다. 줄자 측정 자체가 수 cm의 변동을 갖는데, 모델 오차가 5% 수준이면 두 값이 비슷한 크기다.

## 10. 예상 질문

#### Q001. 이 논문을 설명해 주세요. 🟢

**의도:** 박사 연구와 가장 가까운 논문이므로 반드시 나온다.

**답변:** 스마트폰 LiDAR로 신체 둘레를 자동 측정하는 연구입니다. 핵심은 3D 메시 복원을 하지 않는다는 것입니다. SMPL이나 PIFu 같은 기존 3D 인체 복원 모델은 정밀하지만 고성능 GPU가 필요하고 단일 시점에서 가려진 부분을 추정하기 어려워 모바일 실시간에 맞지 않습니다. 저희는 HRNet으로 측정 지점을 찾고, 그 지점의 깊이만 읽어 3차원 유클리드 거리를 계산하는 가벼운 방식을 택했습니다. 다만 2D에서 찾은 키포인트가 3D 실제 경계와 어긋나는 문제가 있어서, 깊이 맵에 Canny 엣지를 적용해 깊이가 급변하는 지점을 찾고 키포인트를 거기로 옮겼습니다. 정면과 측면에서 잰 둘레를 회귀식으로 합쳐 전체 둘레를 추정했고, 회귀 상수는 한국인 남성 150명의 실측값에서 구했습니다.

**꼬리질문:** 그 보정이 실제로 얼마나 효과가 있었습니까?

#### Q002. 왜 SMPL이나 PIFu 같은 기존 3D 복원 모델을 쓰지 않으셨습니까? 🟡

**의도:** 최신 방법을 몰라서가 아니라 판단으로 배제했는지 확인한다.

**답변:** 세 모델을 검토했는데 각각 다른 이유로 맞지 않았습니다. SMPL은 나체 체형으로 학습된 파라메트릭 모델이라 옷을 입었을 때의 체형과 둘레 변화를 반영하기 어렵고, 단일 이미지에서 파라미터를 추정하려면 복잡한 피팅 절차와 고성능 GPU가 필요해 실시간이 안 됩니다. PIFu는 암시적 함수로 옷 주름까지 잡을 만큼 세밀하지만 단일 시점에서 뒷면이나 가려진 영역을 정확히 추정하기 어렵고 보통 다중 시점 촬영이 필요합니다. DeepHuman은 복셀 기반이라 해상도를 올리면 GPU 메모리와 연산량이 지수적으로 늘어납니다. 공통점은 전신을 복원한 다음 거기서 둘레를 재는 구조라는 것인데, 저희가 필요한 건 특정 지점 사이의 거리뿐이라 그 복원 단계 자체가 과잉이었습니다.

#### Q014. 실측 정답값은 어떻게 만드셨습니까? 🔴

**의도:** 계측 연구에서 가장 날카로운 질문이다.

**답변:** 줄자로 직접 잰 값을 정답으로 썼습니다. 논문에 반복 측정을 했는지, 측정자 간 차이를 확인했는지는 기재돼 있지 않습니다. 이 부분이 계측 연구에서 중요한 이유는, 줄자 측정 자체에 수 센티미터의 변동이 있을 수 있는데 모델 오차가 5퍼센트 수준이면 두 값이 비슷한 크기가 되기 때문입니다. 그러면 보고된 오차가 모델의 부정확함인지 정답의 흔들림인지 구분이 안 됩니다. 특히 둔부처럼 측정 기준 자체가 모호한 부위에서 그렇습니다. 다시 한다면 같은 부위를 여러 번, 여러 사람이 재서 정답의 반복 신뢰도를 함께 보고하겠습니다.

**꼬리질문:** 그럼 지금 보고된 8퍼센트라는 수치가 무의미하다는 겁니까?

#### Q015. 이 논문에서 본인 기여는 무엇입니까? 🔴

**의도:** 3저자 공저이므로 반드시 나온다.

**답변:** 논문의 저자 기여도 항목에 명시된 대로 데이터 큐레이션과 원고 검토·편집을 담당했습니다. 방법론 설계와 소프트웨어 구현은 공동 제1저자인 정용호, 노태욱 두 분이 맡았습니다. 제가 맡은 부분은 `[ 직접 작성 — 어떤 데이터를 어떻게 수집·정리·검수했는지 ]`입니다. 다만 이 연구의 주제 자체는 제 박사 학위논문 주제와 이어져 있어서 방법론 전반은 충분히 이해하고 있고, 방금 말씀드린 한계들도 그래서 정리해 둔 것입니다.

**꼬리질문:** 기여가 데이터 쪽인데 왜 이 주제가 박사 학위논문이 됐습니까?

#### Q016. 정면 둘레와 측면 둘레의 합에 상수를 곱하는 방식은 단면 형태를 무시하는 것 아닙니까? 🔴

**의도:** 방법론의 원리적 한계를 짚는다. 수학적으로 답할 수 있어야 한다.

**답변:** 맞습니다. 정면 폭과 측면 폭 두 숫자만 쓰기 때문에, 같은 두 값을 가져도 단면이 더 납작하거나 더 둥근 사람은 실제 둘레가 다릅니다. 타원으로 근사하는 것보다도 정보가 적은 셈입니다. 그럼에도 R제곱이 0.84가 나온 것은 실제 인체 단면의 형태 변이가 생각보다 크지 않다는 뜻으로 읽었습니다. 다만 형태가 특이한 경우 오차가 커질 것이고, 둔부에서 오차가 컸던 것도 이 지점과 연결될 수 있다고 봅니다. 개선하려면 두 점이 아니라 경계를 따라 여러 점의 깊이를 읽어 단면 곡선 자체를 복원하는 방향이 있는데, 그러면 연산량이 늘어 실시간성과 상충합니다. 어디까지 절충할지가 설계 판단이 될 것 같습니다.

**꼬리질문:** 그 절충점을 어떻게 정하시겠습니까?
